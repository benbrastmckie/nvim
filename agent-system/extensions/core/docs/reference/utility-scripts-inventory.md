# Utility Scripts Inventory

Operator-facing scripts that are not invoked as part of the normal task lifecycle (research /
plan / implement / postflight). Relocated here, unabridged, from CLAUDE.md's "Utility Scripts"
subsection so the eager session-start context prefix does not carry operator-only reference
material. Every entry carried over from the original CLAUDE.md list is unchanged — none was
dropped or summarized away; entries added since the relocation (documented as such, e.g.
`check-runtime-file-tracking.sh` below) are new coverage, not modifications to the original set.

- `.claude/scripts/assess-repo-health.sh` - Standalone repository-health probe: structural `bash -n`/`jq empty` checks over tracked `*.sh`/`*.json`, TODO/FIXME counts, and status derivation, emitted as one JSON `repository_health` object. Called by `/todo`'s Sync Repository Metrics stage (Step 6.5.1)
- `.claude/scripts/validate-return-meta.sh` - The `.return-meta.json` sibling of `validate-handoff.sh`: validates status vocabulary, the strict object-shaped `artifacts` array (bare-string elements FAIL), `type` enum, on-disk path resolution, and required `metadata` sub-fields. `--fix` performs the unambiguous bare-string-to-object repair, opt-in only, never implicit
- `.claude/scripts/export-to-markdown.sh` - Export .claude/ directory to consolidated markdown file
- `.claude/scripts/check-extension-docs.sh` - Doc-lint: validate extension READMEs, manifests, and cross-references (exits non-zero on failures)
- `.claude/scripts/generate-context-line-counts.sh` - Recompute `line_count` from `wc -l` for every entry in every extension's source `index-entries.json` (`--check` reports only, `--write` corrects in place)
- `.claude/scripts/lint/lint-agent-contracts.sh` - Lint agent frontmatter (invalid key detection, `model:` presence), no-task-references bullet coverage, and return-meta `artifacts` object-shaped template presence (Check F) across every dispatchable agent
- `.claude/scripts/lint/lint-routing-wiring.sh` - Lint every manifest's routing wiring: `routing`/`routing_hard` keys have `routing_agents`/`routing_agents_hard` counterparts, and every declared agent name exists on disk
- `.claude/scripts/lint/lint-contract-compliance.sh` - Lint hard-mode H-technique contract wiring: `skill-orchestrate`'s per-phase hard-mode contract injection references the required contracts, all 5 contract files exist with H-technique identifiers, `skill-orchestrate`'s Stage 1b wires the correct per-phase caller-default agent, `skill-orchestrate` declares convergence-policing fields, `context/contracts/anti-analysis.md` carries H2 vocabulary, and `index-entries.json` has no dangling reference to a deleted core hard agent. Wired as a `verify-deploy.sh` gate; not automated beyond that — no other automated caller
- `.claude/scripts/install-aliases.sh` - Installs `claude-refresh`/`claude-refresh-force`/`claude-cleanup` shell aliases. Invoked manually by an operator once per shell setup; no automated caller by design
- `.claude/scripts/install-systemd-timer.sh` - Installs a user-level systemd timer that runs `claude-refresh` hourly to clean up orphaned processes. Invoked manually by an operator; no automated caller by design
- `.claude/scripts/migrate-directory-padding.sh` - One-shot migration of unpadded task directories to the 3-digit zero-padded `{NNN}_{SLUG}` format. Invoked manually by an operator when needed; no automated caller by design
- `.claude/scripts/verify-lean-mcp.sh` - Diagnoses whether `lean-lsp` is correctly configured in user-scope `~/.claude.json` for Claude Code subagents. Invoked manually by an operator; no automated caller by design
- `.claude/scripts/check-runtime-file-tracking.sh` - Dual-purpose, unlike its operator-only siblings above: an operator invokes it directly to verify a consumer repo's git-tracking of orchestrator runtime files (`.orchestrator-handoff.json`, `.return-meta.json`, and other ephemeral-class paths) matches the policy in `context/standards/orchestrator-runtime-files.md` — ignore coverage, no tracked ephemeral files, and provenance files (`.orchestrator-handoff.json`/`.return-meta.json`) not over-ignored. It is ALSO wired in as a mandatory `verify-deploy.sh` gate (Gate 14, "Orchestrator runtime-file tracking policy"), so every deploy-verification run exercises it automatically in addition to any manual invocation
- `.claude/scripts/check-consumer-freshness.sh` - Source-repo-initiated TIER 3 fleet freshness report: for every repo named in `context/reference/known-consumer-repos.json`, reports its per-extension deployed revision and flags those behind source (`--stale-only` for non-fresh rows only; `--discover` reconciles the registry against an on-disk scan). Read-only against every consumer repo; never writes to one. Invoked manually by an operator, and guarded (`--stale-only \|\| true`) from `deploy-headless.sh`'s trailing block, but only when `deploy-headless.sh --consumer-report` is passed explicitly (default OFF, moved off the blocking `/orchestrate` inter-cycle redeploy checkpoint path since it is report-only) — see `context/patterns/regeneration-is-manual-only.md`'s "Tier 3" subsection
- `.claude/scripts/measure-eager-context.sh` - PREDICTS the session-start eager context set from the SOURCE STORE (never the deployed tree, never a real `deploy-headless.sh` regenerate): replicates `generate_claudemd()`'s assembly algorithm in bash, resolves `@`-imports directory-relatively, and derives the eager rule set by glob-matching each rule's `paths:` frontmatter against a documented, overridable representative touched-path set (`--check` reports bytes/tokens per source and exits 0/1 on a volatile-file hit; `--write` additionally records a timestamped JSON drift-comparison snapshot). Coexists with `measure-eager-surface.sh` below rather than superseding it — see that entry for the division of labor
- `.claude/scripts/measure-eager-surface.sh` - Reproducible byte-accounting harness for the session-start eager context prefix, measured against the DEPLOYED `.claude/` tree with a FIXED nine-file/six-rule composition (`--baseline`/`--compare` writes/diffs a JSON snapshot). Useful for apples-to-apples before/after comparison across a single deploy cut. Coexists with `measure-eager-context.sh` above, which is the source-store PREDICTIVE counterpart with DYNAMIC `paths:`-glob rule derivation (intentionally wider — it also counts `error-handling.md` and `workflows.md`, both `.claude/**/*`-gated) and never requires a redeploy to be current
