**Key Decisions Made**:
- The registry interpreter is DELIBERATELY thin: `gate_registry_execute` (and the main loop's
  own `"gate${id}_run"` direct call) does nothing more than look up and call a function. Each
  `gateN_run` function remains fully self-contained (own `gate_selected` check, own
  source-store guard where applicable, own pass/fail/FINDINGS_LIST population) -- a generic
  guard/output fold was judged unsafe for byte-identical output (gate5's SKIP message is a
  genuinely different 2-line shape; gate8 checks `--skip-slow` BEFORE source-store, and a
  generic hoist would silently reorder these checks). `requires_source_store` is still declared
  as ACCURATE metadata (true for 3,5,6,7,8; false for 1,2,4) for a future consumer, just not
  yet consumed to short-circuit a function call.
- DEVIATION: "per-gate state scoped... rather than a single reassigned CURRENT_GATE global" (a
  stated Phase 7 concurrency prerequisite) was NOT attempted in Phase 4 -- each function still
  sets the global `CURRENT_GATE`, identically to the pre-registry code. This is an explicitly
  recorded gap Phase 7 must close, not a silent omission.
- A real bug was caught and fixed during development: `IFS=$'\t' read` silently collapses a
  genuinely empty field between two tabs (bash classifies tab as IFS-whitespace even as IFS's
  sole member), shifting every later column by one. Fixed with a `-` placeholder convention for
  "no dependencies" in `gate-registry.data`, normalized back to empty by
  `gate_registry_load`. Pinned by `test-gate-registry-resolution.sh`'s case6.
- Byte-identical verification: `--only-gate 1,2,3,4,5,6,7,8 --quiet` stdout, stderr, AND exit
  code (rc=1, matching known pre-existing gate3-doc-lint and gate4-citation findings) are
  byte-for-byte identical before vs. after -- saved at
  `progress/phase-4-{before,after}-{stdout,stderr}.txt`.
