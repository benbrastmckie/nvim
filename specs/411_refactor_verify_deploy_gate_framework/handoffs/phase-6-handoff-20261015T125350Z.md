  path. `-k 5` escalates to SIGKILL if a suite ignores SIGTERM; both `timeout`'s own 124 ("TERM
  was enough") and 137 ("128+SIGKILL, escalation fired") sentinels are recognized and produce the
  same named `[FAIL] <suite>` + `TIMEOUT: <suite> exceeded the <bound>s per-suite bound and was

- **Process-group kill, not just the immediate child**: `gate_registry_exec_bounded` runs the
  gate function inside a `set -m` (job-control monitor mode) subshell specifically so its
  backgrounded job gets its OWN process group, and kills `-$pgid` (the whole group) on timeout —

## Key Decisions Made

1. **The timeout-and-reconcile protocol requires the function call AND its `declare -p` state
   dump to happen inside the SAME backgrounded job**, not in a parent subshell that separately
   backgrounds-then-waits. An earlier draft did `"$fn" & wait "$!"; declare -p ...` one level up
   and silently lost every mutation, because `&` always forks regardless of job-control mode, so
   the dump was reading a DIFFERENT process's memory than the one the function actually mutated.
   Fixed by grouping `{ "$fn"; declare -p ...; exit "$rc"; } &` as one job. If Phase 7 forgets
   this and re-derives a scheduler from scratch, it will hit the identical bug.
2. **`timeout`'s own exit-status contract is bimodal (124 vs. 137)**, per `timeout --help`:
   124 when SIGTERM alone sufficed, 137 (128+SIGKILL) when `-k`'s escalation was needed. Both
   must be checked at both of `run-all.sh`'s two call sites (sequential, `run_one()`) or a
   SIGTERM-ignoring stalled suite's timeout detail line silently fails to print even though the
   `[FAIL]` still fires. Proven in test with a `trap '' TERM` fixture.
3. **A real, discovered-by-run-all.sh stalled fixture file (`test-stalled-fixture.sh`) was built,
   tested, then DELETED before commit.** The formal regression cases ended up using fully
   self-contained synthetic fixtures (built fresh inside each test's own `mktemp -d` WORKDIR)
   instead, which is safer (never touches the real corpus) and was already the established
   pattern in both affected test files. The real standalone file was therefore redundant, would
   have been outside task 411's declared `file_scope` (triggering `git-commit-phase.sh`'s
   Containment Self-Check drop-and-warn), and would have added a permanent tiny tax to every
   future real `run-all.sh` discovery run. Do not re-add a real stalled fixture file to the
   actual `scripts/tests/` corpus for this purpose — the synthetic-fixture pattern in
   `test-run-all-selection.sh` PART 3/4 and `test-gate-registry-resolution.sh`'s cases 11-14 is
   the right home for this kind of coverage.
4. **A real flake was caught and fixed during this phase's OWN verification, not downstream**:
   `test-gate-registry-resolution.sh`'s case 13 originally checked for a leftover stalled
   process via `pgrep -f "sleep 30"` — a pattern broad enough to match an UNRELATED concurrent
   sibling suite's own `sleep 30` (confirmed: it failed once inside a real `--only-gate 8`
   battery run, where many suites run in parallel). Fixed to capture and check the SPECIFIC
   child pid the test itself spawned. Re-confirmed clean both standalone (with a deliberately
   injected concurrent `sleep 30`) and inside a real `--only-gate 8` re-run. If Phase 7's own
   concurrency work adds more stalled-fixture tests, use an exact-pid check, never a broad
   `pgrep -f` pattern, for the same reason.

## What NOT to Try

- Do not re-attempt a bare `"$fn" & ...; wait; declare -p ...` shape for the gate-level
  timeout/reconcile mechanism — see Key Decision 1. The function call and its state dump must
  be the SAME backgrounded job.
- Do not rely on `rc -eq 124` alone to detect a fired suite-level timeout — see Key Decision 2.
  Check both 124 and 137.
- Do not add a real, corpus-discovered stalled fixture file under `scripts/tests/` — see Key
  Decision 3. Use a synthetic, `mktemp`-scoped fixture built inside the test itself.
- Do not use `pgrep -f <pattern>` to assert "no leftover process" in any stalled-fixture test
  that might run concurrently with siblings — see Key Decision 4. Capture and check the exact
  pid.
- Do not hand-edit `specs/state.json` with a generic JSON-dump tool (e.g. Python's
  `json.dump` without `ensure_ascii=False`) to adjust `file_scope` or any other field — it
  re-serializes every non-ASCII character in the ~51-project file as `\uXXXX` escapes, producing
  a massive, misleading diff across unrelated projects even though no other project's *content*
  changed. This was attempted and immediately reverted during this phase (restored from a
  pre-edit backup before anything was committed) rather than committed. If a `file_scope`
  addition is ever genuinely needed mid-implementation, prefer leaving the incidental file
  out of the phase's own commit (the Containment Self-Check's designed drop-and-warn behavior)
  over a hand-rolled full-file rewrite of `state.json`.
