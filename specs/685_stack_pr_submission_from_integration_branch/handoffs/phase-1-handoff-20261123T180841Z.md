## Key Decisions Made

- Resolvers (`rsp_resolve_integration_branch`, `rsp_resolve_review_base`, `rsp_resolve_remote`,
  `rsp_detect_platform`) set global variables (`RSP_*`) rather than being called inside
  `$(...)` command substitution: `exit` inside a command-substitution subshell only terminates
  that subshell, silently losing the refusal's exit code. Any later phase adding a new resolver
  to this script MUST follow the same convention -- never wrap a function that may call
  `rsp_refuse` in `$(...)`.
- The "configured upstream remote" step is implemented via `git config --get
  branch.<name>.remote`, never `@{upstream}` ref syntax, specifically to keep the literal word
  "upstream" out of the script (the suite's static assertion forbids it, since PD9/PD1 forbid
  hardcoded remote/branch name assumptions).
- For live, un-deployed testing during this phase, the script was copied by hand into
  `.claude/scripts/review-stack-prepare.sh` (a disposable, gitignored deploy artifact) rather
  than running the full `deploy-headless.sh`. Phase 7 is where the real redeploy happens; do the
  same manual-copy trick for any further phase that needs a live (non-fixture) check before
  then.
