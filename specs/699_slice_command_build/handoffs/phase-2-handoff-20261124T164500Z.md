## Key Decisions Made

- **Dependency readiness is read from the document's own declared `state` field**, not from a
  live content check — `status`'s content-based merged test (Phase 3) is what keeps that field
  honest; `build` itself only ever reads it, never infers merged-ness independently. This keeps
  "no inference code... build decides readiness per invocation from each slice's own depends_on
  states" (the plan's Decision/Research-Integration framing) literal: no topological sort is
  computed across the whole slice set; slices are processed in document order and a dependent
  slice can use a dependency's freshly-computed-this-pass commit opportunistically (via an
  in-memory `commit_for` map), but nothing reorders the array or computes a global build order.
- **State only advances forward** (`proposed` -> `built`), never regressed: a rebuild of an
  already-`pushed`/`open` slice refreshes `commit`/`base_commit` but leaves `state` as-is, since
  `build` itself never knows about push/open transitions — those are `commands/slice.md`'s job.
- **Test-only race seam** (`SS_TEST_PRE_SWAP_HOOK`): see progress file deviation 2.5. Unset in
  ordinary use; does not affect production behavior.
- **Untouched-state assertion scoped to tracked state, not raw `git status --porcelain`**: see
  progress file deviation 2.9 and the issue log (class: ambiguous spec) for the full reasoning —
  build's own required series-document/PR-body writes are new untracked paths, which raw
  `git status --porcelain` would flag as a "change" even though no already-tracked file moved.
