## Decisions

- **Ledger row, not in-source `set_option`, for `unusedArguments`**: `unusedArguments` is raised
  by the batch/environment-linter pass (`lake exe runLinter`), which does not read an in-source
  `set_option` named after a linter it owns, so a `set_option` suppression for this category
  risks a silent no-op (the gate still reports the finding the next time it runs). The uniform
  in-source `set_option` alternative was considered on its own merits (keeps every exemption
  beside its declaration, self-documents, touches no shared file) and rejected specifically for
  that silent-no-op risk, which is a hard failure under `--wfail`. `unusedVariables` and
  `unusedFintypeInType` remain correctly handled by `set_option` because they are genuinely
  elaboration-time categories.
- **`.claude-extensions.json` committed under this phase's `__WHOLE_TREE__` scope via a scoped
  follow-up commit**: the Phase-Commit Containment Self-Check dropped the path from the main
  phase commit because it is not literally enumerated in the task's declared `file_scope` string
  array (only the sentinel token is). This is treated as the mechanism's documented drop-and-warn
  behavior rather than a defect; the follow-up commit via `git-commit-scoped.sh` landed the path
  immediately, following the precedent of an earlier task's phase commit of the same generated
  manifest.
