## Key Decisions Made

- `literature-search.sh` had `has_test: false` going in (script-inventory.sh), so per the plan's
  own "Paired-Test Coverage" instruction, a characterization test (`tests/test-literature-search.sh`,
  49 assertions) was written and confirmed green on the UNMODIFIED script before any edit.
- The duplication here is Python-in-heredoc repetition (5 near-identical helper-function
  definitions re-embedded across `do_search`'s two heredocs, `do_multi_search`, `do_read`, and
  `do_toc`), a different defect class from the cross-file duplicate blocks earlier phases
  addressed. Fix shape: a new file-local Python module
  (`agent-system/extensions/literature/scripts/lib/literature_search_pylib.py`) imported via
  `sys.path.insert` from each heredoc, kept file-local per the plan's own instruction (peers=0,
  no second file needs these helpers).
- The single largest duplicate block was not a helper-function repeat but an entire ~230-line
  second copy of `do_search`'s search pipeline (the "project filter yielded zero rows, retry
  unscoped" fallback, previously a second separately-interpolated `python3` heredoc). This
  collapsed into an in-process retry inside the new `run_single_search()` helper — eliminating
  the second heredoc invocation entirely, not just deduplicating its helper definitions.
- Verification method: the characterization test captures every mode's raw stdout+exit code
  under a `$CAPTURE_DIR`; ran once against the unmodified script (baseline) and once against the
  refactored script, then `diff -r`'d the two capture directories — zero differences across all
  40 captured files (20 modes).
- `agent-system/extensions/literature/manifest.json`'s `provides.scripts` needed the two new
  files registered; `sync-manifest-scripts.sh --check` requires them `git add`-ed first (it diffs
  against `git ls-files`, tracked-only) before it reports green — same mechanic Phase 10's typst
  follow-up commit already hit.
