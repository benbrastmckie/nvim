## What NOT to Try

- Do NOT use `grep -Fqz -- "$pattern" "$file"` (or any `grep -F` form) for multi-line literal
  block containment. `grep -F` splits a multi-line PATTERN argument into one alternative pattern
  PER LINE and reports a match if ANY single line matches ANYWHERE in the target — an OR of
  single lines, not a contiguous substring test (`-z` only changes how the INPUT is
  record-split, never how the PATTERN argument is split). This produced 5/5 false-positive
  VIOLATIONs on the real pilot files (their removed block's generic lines like `` ```bash ``,
  `` ```json ``, bare `{`/`}` trivially recur elsewhere in the same file) despite passing the
  synthetic fixture suite (coincidentally — the tiny fixtures shared no generic lines with their
  host files). Use bash's own `[[ "$content" == *"$pattern"* ]]` instead (quoted expansion
  disables glob interpretation, giving a true literal containment test). Already fixed in
  `lint-anchor-pointer-collapse.sh`; if a future edit to it reintroduces `grep -F`/`grep -Fz`,
  re-verify against the REAL repo, not just the synthetic fixture suite — the fixture suite did
  not catch this bug.
- Do NOT assume the Phase 15 inventory's recorded `anchor_heading` (nearest-ATX-heading-above)
  is the only true anchor location in that file — `early-metadata-pattern.md` turned out to also
  carry a second, more literal "Agent Integration Template" section further down the same file.
  Re-verify by reading the anchor file fully before collapsing, as Phase 15 itself warned.
- Do NOT add a cost hint for a new unit-class test suite to `suite-cost-hints.txt` reflexively —
  it is advisory-only and the run-all.sh note confirms it does not affect which suites run;
  skipped here per this task's own anti-machinery-growth charter.
