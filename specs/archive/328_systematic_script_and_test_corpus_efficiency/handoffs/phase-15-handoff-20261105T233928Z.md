## Key Decisions Made

1. **Gate-required and deliberate-inlining exclusion tests use content-overlap against the
   fragment files' own line set, not file-participant membership in a shared window.** Check
   C/G/L's bullets are held on a single physical line each in the copying file (confirmed by
   reading `no-task-references-bullet.md`'s own "Placement" section), so a window-participant
   test alone would systematically undercount them. This is why the gate-required figure (3,982)
   closely confirms the 3,997 hypothesis while an earlier draft of this same test, before the
   fix, found far less.
2. **Anchor-confirmation uses a strict exact-5-gram test** (the window must recur, verbatim, as a
   contiguous run inside a file under a canonical anchor-category directory — i.e. the anchor
   file is itself one of `window_files[w]`'s members) rather than a looser per-line-presence
   test. The looser version was tried first and discarded for large false positives (documented
   in the progress file's `approaches_tried`). This strict test is explicitly flagged in the plan
   as a conservative floor, not a ceiling — see the plan's "deliberately conservative" paragraph
   for the direct evidence (wrap-up.md confirms correctly; several Scope-Widening-named
   representative blocks do not surface, most plausibly from wording drift, not absence).
3. **`file_scope` widening went through a direct `state.json` edit, not
   `update-task-status.sh --file-scope-add`.** That flag is hard-restricted to
   `operation==postflight && target_status in {research, plan}` and refused this phase's
   mid-implement call with a named validation error. Confirmed via `git diff` that the resulting
   edit is a pure 3-line addition with no reformatting of the surrounding file (an earlier
   attempt via `json.dump` reformatted the entire file and was discarded/reverted before

## What NOT to Try

- Do not use a per-line-presence (rather than exact-contiguous-window) anchor test — it produces
  large false positives on this corpus (common short lines like code-fence markers and generic
  `### Stage N:` headings coincide across unrelated content). Confirmed via direct inspection of
  5 sample "matches," all semantically unrelated to the claimed anchor.
- Do not call `update-task-status.sh --file-scope-add` from inside an implement-phase dispatch —
  it is postflight/research-or-plan-only by design and will refuse with a validation error.
- Do not use `json.dump()` (or any full-document JSON re-serialize) to edit `specs/state.json` —
  `ensure_ascii=True` (Python's default) silently converts every literal Unicode character
  (em-dashes, etc.) anywhere in the 3,000+-line file into `\uXXXX` escapes, producing a
  file-wide diff for a 3-line intended change. Use targeted `Edit` calls against unique
  surrounding context instead.
