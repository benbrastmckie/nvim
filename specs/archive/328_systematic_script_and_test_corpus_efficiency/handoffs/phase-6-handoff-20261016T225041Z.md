## Key Decisions Made

- **Partial, shape-aware migration per suite, never forced.** Of the 18 non-lint suites, the
  trio (pass/fail/info) and the `source common.sh` line were migrated on all 18; `REPO_ROOT`
  resolution was migrated to `common_test_repo_root` on 10/18 (only where the git-rev-parse +
  fixed-depth-fallback shape matched exactly, preserving the detected fallback-level count as the
  function's second argument when it was not the harness default of 5); `WORKDIR` + trap EXIT was
  migrated to `common_test_workdir_init` on 14/18 (only for the exact `WORKDIR="$(mktemp -d)"` +
  single-EXIT-trap shape); a local `resolve_candidate()` was migrated to
  `common_test_resolve_candidate` on 4/18 (only where the body matched the canonical shape
  structurally). Suites with no recognized shape for a given piece were left untouched on that
  piece — the same reasoned-partial-migration precedent Phase 5 set for the lint cluster.
- **Swapped one tranche member for cost, not just line count.** `test-verify-deploy-gate-
  selection-crash-net.sh` is 109 lines (would have been the smallest candidate) but costs
  148,607ms per `suite-cost-hints.txt` — a heavyweight integration suite, small only by line
  count. Swapped for `test-mint-dispatch-seq.sh` (257 lines, 314ms) to keep this tranche's own
  verification loop fast and keep the tranche's character (small, cheap, standard-shaped suites)
  honest.
- **Folded dropped second-argument diagnostics into the message string.** Several suites' local
  `fail()` definitions accepted an optional second argument printed as extra diagnostic context
  on failure (`fail "$msg" "$extra_output"`). `common_test_fail` takes exactly one argument, so
  all such call sites were rewritten to `common_test_fail "$msg: $extra_output"` — preserving the
  diagnostic content (never exercised today since every migrated suite is currently green) while
  conforming to the shared function's signature.

## What NOT to Try

- **Do not write a single generic regex pass assuming every `pass`/`fail`/`info` definition and
  every call site is single-line and line-start-anchored.** Two concrete failure modes were hit
  and fixed in this phase:
  1. A deletion regex for one-line trio definitions (`^(?:pass|fail|info)\(\)\s*\{[^\n}]*\}`)
     breaks on a definition containing a literal `}` inside `${VAR}` brace-interpolation on the
     same line (e.g. `fail() { echo -e "${RED}[FAIL]${NC} $1"; ... }` or
     `fail() { ...; [ -n "${2:-}" ] && echo "$2"; }`) — the `[^\n}]*` stops at the interpolation's
     own closing brace, leaving a dangling fragment that breaks `bash -n`. Caught immediately by
     a syntax check; fix was a manual, file-specific edit rather than a smarter regex.
  2. A call-site rename anchored to line-start (`^[ \t]*pass "`) misses call sites inside
     case-statement arms (`pattern) pass "msg" ;;`) and single-line `if ...; then pass "msg"; fi`
     shapes. Once the local `pass()` definition is deleted, an unrenamed `pass "msg"` call falls
     through to the real UNIX `pass` password-store binary on `PATH`, which fails with "Error:
     ... is not in the password store." — a RUNTIME symptom, not a syntax error, and it silently
     drops assertion counts (one suite's reported `PASSED` dropped from 28 to 5). This is caught
     only by actually running the suite and diffing output against a captured baseline, never by
     `bash -n` alone — confirms why this phase's own verification criterion (run before AND
     after, diff the output) is load-bearing and not a formality.
- **Do not treat a non-byte-identical post-migration diff as an automatic failure without reading
  it.** Two of the 25 suites' output differs cosmetically (an `[INFO] ` prefix gained by
  standardizing on the shared helper's format; ANSI color codes dropped). Both are expected,
  harmless, and consistent with `shell-script-testing.md`'s own required format — the actual
  invariant (assertion count, PASS/FAIL case-name text, and the `^[FAIL] ` prefix `run-all.sh`
  parses for failure detection) was unchanged in both cases.

## Critical Context

- The `common_test_*` harness functions live in `agent-system/extensions/core/scripts/lib/
  common.sh` (added in Phase 4), not in a separate `test-harness-lib.sh` file — Phase 4 found
  `common.sh` already carried the `pass`/`fail`/`info` output-string trio unused, and extended it
  in place rather than creating a parallel library. Any future migration phase sources
  `"$SCRIPT_DIR/../lib/common.sh"`, never a `test-harness-lib.sh` path.
- `grep -nE '^(pass|fail|info)\(\) \{' <file>` is the exact anti-regression check this plan uses
  to confirm no local redefinition remains — reuse it verbatim for Phases 7-8's own verification.
- `suite-cost-hints.txt` (format: `basename,wall_ms`, NOT `basename:wall_ms`) is the cheap way to
  avoid picking a small-by-line-count-but-expensive-by-runtime suite for a "smallest suites"
  tranche, as this phase's crash-net swap demonstrates.
