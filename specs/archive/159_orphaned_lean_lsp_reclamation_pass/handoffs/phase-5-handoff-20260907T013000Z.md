## Key Decisions Made

- **Critical bash gotcha discovered and worked around**: `kill` is a shell BUILTIN. The
  established `PATH="$FAKE_BIN_DIR:$PATH" ... bash script.sh` pattern (used successfully for
  `ps` throughout this suite) does NOT intercept `kill` calls -- bash resolves builtins before
  consulting `$PATH`. First attempt produced "PID N: already gone" for every synthetic PID (the
  REAL `kill -0` correctly reported nonexistent PIDs as dead). Fixed by wrapping the `--force`
  invocation in `bash -c '... enable -n kill; ... source script.sh; main --force'`, which
  disables the builtin for that one dedicated subshell before the script is sourced (sourcing,
  not executing, also means the script's own `BASH_SOURCE[0]==$0` guard does not auto-run
  `main()`, so it must be called explicitly after `source`).
- Non-vacuousness of the ORDERING assertion verified directly: temporarily reordered
  `ordered_pids` construction to root-first, confirmed RED (48/49, ORDERING assertion failed),
  reverted, confirmed GREEN (49/49) again.
- Recorded a deliberate deviation on Phase 5's first task: the fake `ps` answers every
  invocation shape itself rather than delegating non-matching calls to a resolved real `ps`
  (the (d-2) ancestry-walk technique) -- not needed here since none of this fixture's 5 rows
  need to distinguish the running test script's own pid.
