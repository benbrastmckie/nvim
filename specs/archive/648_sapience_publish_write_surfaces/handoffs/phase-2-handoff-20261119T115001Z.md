## What NOT to Try

- Do not call `sapience_post` via `x="$(sapience_post ...)"` when the HTTP status is needed
  afterward -- command substitution forks a subshell and silently drops
  `sapience_api_post_http_status`. Use `_sapience_post_capture` instead.
- In `test-sapience-publish.sh`'s curl-stub-driving env vars, never reuse a name the script
  itself parses as a flag variable (e.g. `DM_BODY`, `COMMENT_BODY`) -- the script's own
  assignment overwrites the exported fixture value before curl ever runs. The suite now uses
  `STUB_`-prefixed names throughout for this reason; keep that convention for any new stub env
  var added in Phase 3/4 (e.g. `STUB_DOCVER_BODY`/`STUB_DOCVER_CODE`, already reserved in the
  stub's own `case` dispatch but not yet exercised by a test case).
