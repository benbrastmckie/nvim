## What NOT to Try

- Never write `cmd 2>/dev/null >&2` when the intent is "send cmd's stdout to the real stderr
  while suppressing cmd's own stderr" -- bash redirections apply left-to-right, so this silently
  discards BOTH streams. The correct order is `cmd >&2 2>/dev/null` (dup fd1 from the still-live
  fd2 first, then redirect fd2 away). Grep the file for this exact anti-pattern before adding
  any new diagnostic print in Phase 4's `ko` subcommand.
- Continue honoring Phase 2's `_sapience_post_capture` rule for any new POST call site that
  needs `sapience_api_post_http_status` (the `ko` subcommand's `/ingest-kos` call will need
  this).
