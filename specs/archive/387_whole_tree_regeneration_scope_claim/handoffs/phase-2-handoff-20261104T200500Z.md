## IMPORTANT — Design finding for Phase 4 (read before starting Phase 3/4)

Both `WHOLE-TREE-CODISPATCH` and `WHOLE-TREE-PHASE-EXEMPT` are RED today, but via a DIFFERENT
mechanism than the plan's Design Decisions section assumed:

The plan assumed today's unmodified `orchestrate-batch-admit.sh` would falsely ADMIT a
disjoint-real-scope-but-both-sentinel-carrying pair, because "no existing predicate reads the
claim." In fact, the EXISTING `file_scope_collision` exact-match branch ALREADY defers the pair
today: both candidates declare the IDENTICAL literal `"__WHOLE_TREE__"` string, and
`scopes_overlap_first`'s exact-match rule fires on identical strings regardless of slashes. The
plan's "the sentinel is inert in both predicates" claim is scoped to inertness **against a real
path** (confirmed correct by the GREEN `WHOLE-TREE-INERT-PATH` case) — it does NOT mean inert
against another instance of itself.

Today's wrongness is therefore: the pair DOES defer, but with the WRONG `defer_reason`
(`file_scope_collision`, `overlapping_path: "__WHOLE_TREE__"`), missing `claim_sentinel`/
`whole_tree_claim`, and (critically) `--phase-map` has NO effect on it — the phase-exempt case
defers exactly the same way, ignoring the exemption entirely.

**Consequence for Phase 4**: the plan's stated mechanism — "a new, fifth admission dimension...
evaluated LAST... only on a candidate the three existing post-absence branches would otherwise
ADMIT... no existing branch's code path is edited" — CANNOT work as literally written for the
same-sentinel in-batch case, because the plain exact-match collision scan intercepts and defers
it first, before a last-ranked dimension would ever be reached. Phase 4 must resolve this
tension. The most likely fix: give the whole-tree-claim check (with its own `defer_reason`,
fields, and `--phase-map` exemption) first look — or a short-circuit — specifically when the
colliding `file_scope` entry on BOTH sides equals the reserved sentinel, falling through to the
ordinary exact-match collision reason only when the colliding entry is a real path. This must
not disturb the exact-match branch's behavior for any real-path collision (Case 1/2's
non-regression pins must stay green).

Recorded via `issue-record.sh` (class `design-gap`, severity `costly`) and in inline comments at
both fixture sites in `test-orchestrate-batch-admit.sh`. Full narrative:
`specs/387_whole_tree_regeneration_scope_claim/progress/phase-2-progress.json`'s
`design_finding` field.
