- Corrected the plan's literal `$WORKDIR/exts/core` fixture-depth shorthand to
  `$WORKDIR/agent-system/extensions/core` (two levels under `$WORKDIR`, matching the real
  repository exactly). This was necessary, not cosmetic: `tests/run-all.sh`'s
  `GATE_TASK_LOCK_SH` resolution walks two levels up from `EXTENSIONS_ROOT`, and
  `task-lock.sh`'s own `PROJECT_ROOT` resolution walks two levels up from its
  `.claude/scripts/task-lock.sh` location — both must land on `$WORKDIR` for the mutex to
  actually appear at `$WORKDIR/specs/.gate-lock` as the plan itself requires. Documented in the
  plan's own Phase 4 body as a "Fixture-depth precision note."
- The stale/killed-holder case backdates the mutex's own `claimed_at` file instead of a real
  sleep, matching this codebase's established no-sleeping controlled-epoch convention
  (`test-task-lock-liveness.sh`/`test-task-lock-reap.sh`). The literal `kill -9` against the
  acquiring child is a defensive no-op (the child has already exited by the time it runs, since
  `gate-acquire` is a bounded, non-blocking call once it succeeds) — "without releasing" is
  satisfied by simply never calling `gate-release` for that token before backdating.
