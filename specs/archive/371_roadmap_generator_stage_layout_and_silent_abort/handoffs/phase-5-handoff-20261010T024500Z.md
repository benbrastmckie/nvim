## IMPORTANT: a pre-existing, out-of-scope bug was discovered and left unfixed

Verifying `--prune` against BimodalLogic's real `specs/ROADMAP.md` surfaced a genuine,
pre-existing defect in `prune_next_body()` (shared by both layouts, NOT modified by this task):
when a Run line's task list is followed by a CLI flag before its rationale comment (e.g.
`/orchestrate 716,714 --hard   # rationale`), the flag text gets concatenated onto the last task
id during parsing (`714--hard`), which then fails the active-ids lookup and gets silently
dropped as if terminal -- and the flag text itself vanishes. Reproduced minimally against the
CLASSIC layout too: `/orchestrate 1,2 --hard   # rationale` with task 1 terminal and task 2
ACTIVE collapsed the entire line to empty, silently dropping an active task's scheduling.

This is NOT fixed in this task: it is unrelated to `extract_section`/layout detection, and the
task description explicitly scopes `--prune` behaviour changes to "only if the shared
`extract_section()` fix touches it" -- it does not. Recorded via `issue-record.sh` (class
`latent-defect`, severity `costly`) for a future task. **Flag this prominently in the final
summary** so it reaches the user, since it affects the already-shipped classic `--prune` path
too, not just this task's new stage-layout work.
