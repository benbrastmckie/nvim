## Key Decisions Made

- Degradation to a direct in-place `execvp` happens only on `pty.openpty()` failure; a
  termios-setup failure on the proxy's own (non-essential) stdin raw-mode step instead just
  skips raw mode and continues proxying (still styled, just without perfect keystroke-level
  raw forwarding) -- a stricter reading of the plan's wording would degrade to bare `sf1` on
  *any* termios issue, but since raw-mode only affects the proxy's own stdin (not the child's
  pty, which always gets its own default canonical settings), failing open here is strictly
  better: it keeps styling in exactly the cases that matter.
- `child executable not found` is handled naturally by the existing fork+exec+`os._exit(127)`
  path (the child process itself emits the message and exit code, which propagates through
  `waitpid`/`_status_to_exit_code` like any other child exit) -- no separate pre-fork
  `shutil.which()` check was needed.

## What NOT to Try

- Do not write a stub-child smoke test that waits on a *second* `input()` call after closing
  the test's own stdin pipe: closing this process's stdin only stops forwarding into the
  child's pty, it does not deliver EOF to the child's still-open pty slave (exactly like a real
  terminal) -- the stub hangs forever waiting for a keystroke that will never arrive. The fix is
  to make the stub exit without waiting on a second line, not to chase an EOF-propagation
  mechanism that would not reflect real `<leader>as` usage anyway.
