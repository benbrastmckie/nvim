## Deviations from Plan

- **Test-suite bug found and fixed during verification, not a plan deviation but worth
  recording**: the test suite's own `read -r scratch recorder < <(build_scratch --with-stub)`
  pattern does not actually capture two lines (bash `read` splits one line across multiple
  variables, it does not read multiple lines into multiple variables) — fixed to
  `mapfile -t _bs < <(...)`. A second, related bug: `grep -c ... || echo 0` double-prints when
  grep finds zero matches (grep itself prints "0" to stdout AND returns exit 1, triggering the
  `|| echo 0` fallback too, producing two lines "0\n0" where one integer was expected) — fixed
  to capture grep's own stdout via `n="$(grep -c ... )" || true; echo "${n:-0}"`. Both bugs were
  caught by actually running the suite rather than only shellcheck, and are fixed in the
  committed file; the final run is 31/31 PASS.

## What NOT to Try

- Do not expect `postflight-sapience-notes.sh --dry-run` to run directly from the source store
  against this task's own real `.return-meta.json` for a "live" smoke check: it sources
  `deploy-root-guard.sh` from its own `${SCRIPT_DIR}`, which does not exist as a sibling in the
  source store (only post-deploy, where every extension's scripts/ are flattened into one
  `.claude/scripts/` tree). This is the SAME constraint `sapience-remember.sh` itself documents.
  Phase 2's "live, un-stubbed `--dry-run` smoke run against this task's own directory" verification
  bullet is therefore satisfied by the manual scratch-fixture smoke test (step 1 above, run in a
  deployed-tree-shaped fixture with the real `sapience-remember.sh`, confirming
  `[repo:<slug>]`-tagged, token-redacted output with zero network calls) rather than literally
  against this repo's own un-deployed source tree; the REAL post-deploy live attestation against
  this actual deployed tree happens in Phase 6, which already plans the identical check (4-note
  and 0-note fixtures).
