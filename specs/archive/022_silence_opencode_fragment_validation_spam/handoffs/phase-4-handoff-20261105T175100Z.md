## Key Decisions Made

- Registry location: `vim.fn.stdpath("data") .. "/neotex-ai/extension-repo-registry.json"`,
  reusing the established `data_dir` convention from `ai-tool-picker.lua` rather than inventing a
  new global-data location.
- Host-repo exclusion: `M.is_host_repo` compares `vim.fn.resolve(project_dir)` against
  `vim.fn.resolve(vim.fn.stdpath("config"))`. `manager.load`'s hook calls `M.upsert`
  unconditionally; `upsert` itself no-ops (returns `true, nil`) when the target is the host repo,
  so the host repo is never registered and `Global Update` cannot recurse into itself.
- `config.lua` was deliberately NOT modified (a plan-conditional task: "if the investigation step
  concludes it belongs with the other path config"). The registry is preset-agnostic and spans
  every repo, whereas `config.lua` is per-preset (claude/opencode); the location constant stays
  local to `repo_registry.lua`.
