## Overview

Closed the one measurably-unmet requirement from this record's description: a declaration-order
dependent masking where two tasks that each declare the reserved `__WHOLE_TREE__` sentinel AND
also genuinely collide on a concrete real path were reported as a bare whole-tree claim (no
`overlapping_path`, a `claim_sentinel` field present) whenever the sentinel happened to be
declared before the shared concrete path in either task's `file_scope` array. All three plan
phases completed: a RED-for-the-right-reason pinning fixture, the production fix (an additive
precedence wrapper composed from the existing overlap predicate), and a redeploy that cleared the
`core` extension's reported staleness.

## What Changed

- `agent-system/extensions/core/scripts/lib/file-scope-overlap.sh` -- added
  `scopes_overlap_first_preferring_concrete(own_scope; other_scope)` immediately after
  `scopes_overlap_first`, which it is left byte-identical. The new def filters the reserved
  `__WHOLE_TREE__` sentinel out of both scopes and compares the filtered pair first, falling back
  to the unfiltered `scopes_overlap_first` call only when the filtered comparison finds nothing.
- `agent-system/extensions/core/scripts/orchestrate-batch-admit.sh` -- the single per-peer overlap

  `scopes_overlap_first_preferring_concrete(...)`; nothing else in that comprehension changed.
  Added a short header-block note recording that a sentinel-shaped verdict now fires only when the
  colliding pair has no concrete overlap.
- `agent-system/extensions/core/scripts/tests/test-orchestrate-batch-admit.sh` -- added fixture
  `WHOLE-TREE-REAL-PATH-PRECEDENCE` (sub-cases A and B, task numbers 409-412), pinning that both
  declaration orderings of a sentinel-plus-shared-concrete-path pair now report
  `file_scope_collision` with the concrete `overlapping_path` and no `claim_sentinel`. No
  pre-existing assertion was edited.
- `.claude-extensions.json` -- regenerated by the Phase 3 redeploy (tracked bookkeeping file the
  deploy rewrites; declared in the task's `file_scope` for exactly this reason).
- Deployed tree -- regenerated via `deploy-headless.sh`; the `core` extension's reported

## Decisions

- Converted the new def's internal filtered-sub-comparison `empty` result to `null` via
  `[scopes_overlap_first(...)] | first` (the same idiom `self_mod_match` already uses) before
  branching on it, so that binding the filtered comparison's result via `as` does not
  short-circuit the fallback branch when the filtered comparison finds no hit. The def's own
  overall return convention still mirrors `scopes_overlap_first`'s `empty`-on-no-hit convention,
  since the only known caller binds it via `as $ov_path` inside an array comprehension.
- Left the no-co-admission posture, `scopes_overlap_first` itself, which peer `$hit` selects, and
  every defer-direction rule completely untouched, per the plan's Non-Goals. A cross-peer masking
  case (one peer colliding on the sentinel, a different peer colliding on a concrete path) was
  identified and deliberately left unclosed, recorded via `issue-record.sh` rather than acted on.
