## Key Decisions Made

- A line carrying BOTH a begin and an end marker substring (Case: "begin and end on same line",
  pinned in Phase 2's library suite) is treated as a self-contained pair with no net stack
  effect -- this decision lives in the shared library (Phase 2), not this hook, but the hook's
  Edit-path region resolution depends on it being correct.
- `nlcount` (literal newline-BYTE count) is used, not a "line count" that would behave
  differently for a possibly-unterminated final line -- this exactly matches the plan's own
  stated formula and keeps the inserted-range math simple and auditable.
- `mapfile ... < <(printf '%s' "$MERGED" | ...)` (process substitution) is used instead of a
  `<<<` here-string for both the mask array and the line array -- a here-string silently adds an
  extra trailing newline, which would desynchronize the two arrays by one entry whenever the
  merged content already ends in a newline (the common case). This was caught by direct testing,
  not anticipated in the plan text.

## Deviations from Plan

## What NOT to Try

- Do not write literal `task-ref-ok:begin`/`task-ref-ok:end` substrings directly into a new test
  fixture's source for a deliberately unbalanced on-disk scenario (unterminated begin) -- compose
  via concatenation (see `EDIT_MARK_BEGIN`/`EDIT_MARK_END` in `test-validate-no-task-references.sh`)
  or the file's own balance trace will flag it.
- Do not cite a literal task-number digit directly inside a heredoc body meant to be written to
  an on-disk fixture file when that heredoc appears inside this phase's own test-script source
  (the OLD, still-deployed hook scans the Edit's whole `new_string` payload at write time) --
  route the citation through a variable assigned on its own line with a trailing inline
  `# task-ref-ok` comment, then interpolate the variable into an UNQUOTED heredoc.
- The currently deployed hook (`.claude/hooks/validate-no-task-references.sh`) is STILL the old
  payload-only one until Phase 5's redeploy.
