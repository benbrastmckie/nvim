## Key Decisions Made

- The validity rule's "outermost still-open begin" is tracked via a line-number stack built in
  one pass; at EOF the bottommost remaining stack entry is the outermost unclosed begin. A
  second pass applies the normal well-formed-prefix logic before that line and marks everything
  from it through EOF as not-exempt (except bare inline-marker lines, which keep their own
  exemption per the plan's explicit carve-out).
- A line carrying both a begin and an end substring is treated as a self-contained pair with no
  net effect on the stack (push-then-immediately-pop), rather than letting the begin-pattern's
  earlier-checked-wins quirk from the old toggle leave it open. This is a new, explicit decision
  (the plan listed the case but did not prescribe the resolution) and is pinned by Case 7 in the
  new suite.
- `marker_balance_report` treats either `eof_depth > 0` OR `stray > 0` as invalid (matches the
  Phase 1 balance-trace snippet already in the plan), even though only `eof_depth > 0` triggers
  the not-exempt span for `strip_exempt_regions`/`exempt_line_mask`. A stray end alone is
  reported but does not retroactively exempt-or-un-exempt anything (Case 3).
- The new test suite composes every marker-token fixture (including deliberately unbalanced
  ones) at runtime via string concatenation, and keeps every literal task-number citation in its
  own variable assignment with a trailing inline exemption comment -- so the new file's own
  marker-hygiene trace is trivially balanced (zero occurrences) rather than needing its own
  wrapper pair.
