## Deviations from Plan
- Candidate #713 (specs/ carve-out) surfaced a genuine test-harness gap: `setup_sandbox()` never
  copied `generate-task-order.sh`, a hard dependency of `generate-todo.sh` (sourced via
  `"${SCRIPT_DIR}/generate-task-order.sh --print"`). Without it, TODO.md regeneration silently
  failed in EVERY existing fixture (a non-fatal "Warning: generate-todo.sh failed" on stderr,
  state.json unaffected) — undetected until now because no prior fixture asserted on TODO.md's
  actual content. Fixed by adding `generate-task-order.sh` to both the `require_file` loop and the
  `setup_sandbox()` copy loop, with an explanatory comment matching the existing
  hard-dependency-comment pattern (see the `return-meta-status-vocabulary.sh` comment immediately
  above it for the precedent). This is a harness fix, not a SUT behaviour change — recorded as a
  deviation (altered) in the Phase 3 progress file, not silently folded in.
- A companion discovery while debugging #713: a fixture whose dispatched task transitions all the
  way to a terminal status (`completed`) can make a regenerated TODO.md come back
  BYTE-IDENTICAL to a bare `"## Tasks"` baseline (the completed task simply disappears from the
  active list), which would make a naive "TODO.md is in the commit diff" assertion pass for the
  wrong reason (no real diff to detect). Worked around by seeding #713's baseline TODO.md with a
  stale placeholder line that cannot coincidentally match any real regenerated output.

## What NOT to Try
- Do not assert on TODO.md's presence in a commit diff without EITHER confirming
  `generate-task-order.sh` is present in the sandbox OR seeding a stale, impossible-to-coincide
  baseline (ideally both, as #713 now does).
- Do not write a literal "task #<digits>" string in test/source text for an expected-warning
  assertion — use a shell variable (see #790's `zm_num` pattern) so the no-task-references
  write-time hook does not block the edit.
