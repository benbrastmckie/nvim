**Key Decisions Made**:

  em dash and right-arrow byte sequence in `title`; project 3's `file_scope` is the only field
  either transform intentionally changes.
- The hazard transform uses `json.load` + append + `json.dump(..., indent=2)` with
  `ensure_ascii` left at its Python default (`True`) -- not passed explicitly -- matching the
  originating incident exactly.
- The remedy transform uses `jq --arg new_file "new_file.py" '... += [$new_file]'` rather than
  `--argjson` (the plan said "`--argjson`-style" generically; `--arg` is the correct flag for a
  plain string value, `--argjson` is for JSON-typed values).
- Assertions check both the diff shape (whether `"title"` appears in the diff at all) and the
  literal byte content (grep for the raw UTF-8 em-dash/arrow bytes vs. the `—`/`→`
  escape sequences), so the case fails loudly on either a reasoning slip or an environment
  encoding quirk, not just on the diff's line count.

**Deviations from Plan**: See progress file's `deviations` array -- Task 3.4 used `jq --arg`
rather than `--argjson`, reason recorded there and in the plan's checklist annotation.

trailing newline where the heredoc-written original has one, adding one incidental extra diff
hunk unrelated to the hazard) -- assert on content (presence/absence of `"title"` and of the
specific escaped/unescaped byte sequences) instead, which is what this phase's cases do.
