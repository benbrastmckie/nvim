  `bash <source_dir>/scripts/verify-deploy.sh <source_dir>` phrasing does not resolve against
  verify-deploy.sh's own TARGET validation. `verify-deploy.sh:391` requires `TARGET/.claude` to
  exist and `verify-deploy.sh:418` gates the source-store shared-corpus build on
  `TARGET/agent-system/extensions` existing — both true only at the repo root
  (`/home/benjamin/.config/nvim`), never at the extension's own `source_dir`
  (`agent-system/extensions/core`). Passing the extension's `source_dir` as `TARGET` fails fast
  with exit 2 (`no deploy tree`). Resolved `<source_dir>` to the repo root for every
  full-battery invocation in this phase. The script itself still lives under
  `agent-system/extensions/core/scripts/verify-deploy.sh`; only the TARGET argument differs.
- **No literal pre-task findings capture exists** for objective 4's "against the pre-task
  capture" phrasing. Phase 5's own progress file (`deviations[0]`) already established the same
  substitution precedent mid-task: a byte-diff against a pre-task baseline is not meaningful once
  the source store has been edited across ten phases, so finding-set equivalence here means
  "every finding traces to an already-documented pre-existing cause," not a literal byte-diff.
- **Transient-contention findings excluded from the regression conclusion, not silently
  dropped**: both anomalous findings (gate4 timeout, test-update-task-status.sh) were
  investigated with a standalone reproduction before being excluded, and both are recorded in
  `issues.jsonl` rather than only in this handoff.
- Exactly two full-battery runs were used, per the dispatch's explicit budget, with the second
  run's `--jobs 2` also serving as the determinism data point (reusing run 1's `--jobs auto` as
  the first).
