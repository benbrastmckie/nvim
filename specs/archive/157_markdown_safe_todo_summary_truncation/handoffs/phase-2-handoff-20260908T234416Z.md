## Key Decisions Made
- Chose the STRIP approach over parity-balancing, per the plan's recorded decision: strip
  backtick, asterisk, underscore, and open-bracket unconditionally before slicing, rather than
  appending a closing backtick when the naive count is odd.
- Budget semantics: "no line exceeds the budget" is interpreted as the TOTAL rendered length
  (content + marker) never exceeding the stated budget (65 for the primary slice, 40 for the
  cross-topic slice) -- so truncation reserves 3 characters for the "..." marker within the
  budget, rather than appending the marker on top of a full-budget slice.
- The cross-topic short_desc branch (the 40-char slice) is reachable in the live code ONLY via
  an Uncategorized (topic-less) bridging task, because the successor skip-check that would
  normally block a cross-topic edge only fires when the current section's topic is non-empty.
  Both case-group-4 fixtures use this recipe (documented in the test file's case-group-4
  header comment).
