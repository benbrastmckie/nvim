## Key Decisions Made

- **`land` refuses outright when invoked from inside a worktree's own hardlinked
  `.claude/scripts/`** (verdict `unavailable`, exit 93) — PROJECT_ROOT would otherwise resolve to
  the worktree, not the main tree, and land would silently merge into the wrong checkout. This was
  not explicitly in the plan's Phase 5 task list; recorded as a deliberate strengthening (see
  `progress/phase-5-progress.json`'s `deviations`).
- **The "already fully landed" check runs BEFORE the specs/** and dirty-overlap refusals**, via
  `git merge-base --is-ancestor <branch> HEAD`. This makes `land` idempotent: re-invoking it after
  a clean land (or against a branch that never diverged) reports `nothing_to_land`, exit 0,
  without re-running any refusal logic.
- **A genuine conflict is reproduced with an add/add fixture** (both the branch and the main tree
  independently add the same new filename with different content after the branch forked), not a
  same-line edit conflict — simpler fixture, equally genuine `git merge` conflict, no pre-seeded
  shared content needed.
- **Every `git merge`/`git merge --abort` invocation is redirected with a bare `>&2`** (not
  captured into a variable) so its own stdout never lands on the script's stdout — the JSON
  verdict is the ONLY unredirected stdout write per invocation. Confirmed via
  `lint-json-channel-discipline.sh --verbose dispatch-worktree.sh`: PASS, zero violations.
- **Redeployed after this phase too** (`bash .claude/scripts/deploy-headless.sh`); confirmed the
  deployed `.claude/scripts/dispatch-worktree.sh --help` lists `land` and its exit codes.
  `check-extension-docs.sh` still reports `core PASS`; the sole remaining `literature` extension
  failure is the same PRE-EXISTING, unrelated defect noted in the Phase 4 handoff (out of scope,
