**Key Decisions Made**:
- Confirmed form: a bare `&`-backgrounded shell child survives past the launching Bash tool

**Deviations from Plan**: None.

**What NOT to Try**: Do not attempt to `wait "$pid"` for a backgrounded process across SEPARATE
Bash tool calls — it returns 127 ("no such job") because each tool call is a distinct shell and
the PID is not that shell's own child. The wait/exit-code capture must happen in the SAME Bash
call that launched the background process (this is itself part of why the canonical idiom is a
single call, not a tool-level background+poll pattern).
