## What NOT to Try

- Do not attempt `git add -A`, `git add .`, or a bare directory pathspec inside ANY scratch git
  repository, even a throwaway one under `/tmp` unrelated to this project -- `guard-destructive-
  git.sh`'s over-staging predicate is a pure command-text match with no cwd-awareness and refuses
  it regardless of target repo. Use `find -type f -print0 | xargs -0 git add --` (an explicit file
  list) instead.
- When building a temporary instrumented copy of a test suite for measurement, do NOT run it from
  a scratch tmpdir -- these suites resolve `verify-deploy.sh` and similar paths relative to their
  OWN `SCRIPT_DIR`/`CORE_DIR`, which breaks when the copy's location changes. Place the copy
  in-place under a name that will not match `run-all.sh`'s `test-*.sh` discovery glob, run it,
  then delete it immediately -- never leave it behind, even briefly, since a concurrent sibling
  session could otherwise discover or commit it.
- When wrapping a helper function to add timing instrumentation, explicitly capture and `return`
  its real exit code (`local _rc; ...; _rc=$?; ...; return "$_rc"`) -- a wrapper whose last
  statement is a `printf`/`echo` silently collapses the wrapped command's exit code to 0/whatever
  that last statement returns, which can flip an exit-code-asserting case's result without any
  change to the underlying production behavior being measured.
