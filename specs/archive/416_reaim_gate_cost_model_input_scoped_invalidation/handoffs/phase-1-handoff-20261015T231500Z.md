## Key Decisions Made

- **Row/header shape**: `gate_id,run1_ms,run1_load,run2_ms,run2_load,...,avg_ms,cost_class,valid`
  (run_ms/run_load interleaved per run, not grouped). `avg_ms` is still computed from `run*_ms`
  only.
- **Empty/unreadable load read never marks a row invalid** -- matches the pre-existing
  "proceed, but UNVERIFIED" posture for an unreadable `/proc/loadavg`; only a load that was
  actually read AND exceeds the threshold marks invalidity.
- **Overwrite protection fires on exactly one collision**: prior artifact header reads
  `# ALL_VALID=true` AND the new run is NOT all-valid. Every other combination (no prior
  artifact, prior artifact already not-all-valid, or a new run that IS all-valid) overwrites
  normally. This is deliberately asymmetric -- a contaminated run never needs "protecting" from
  being overwritten later by a clean one.
- **New env-var test seam**: `MEASURE_GATE_COSTS_LOADAVG_SEQUENCE` (comma-separated values) +
  `MEASURE_GATE_COSTS_LOADAVG_SEQFILE` (counter-file path, for test isolation) lets a test
  advance through a sequence of load readings across repeated `mgc_load_1min` calls -- the
  pre-existing static `_OVERRIDE` hook returns one value for an entire run and cannot simulate a
  rise. Both hooks coexist; `_SEQUENCE` is checked first.
- **Exit code 2 is reused**, not a new code, for "contaminated run refused from overwriting a
  clean artifact" -- it already meant "usage error, or the load guard refused," and this is the
  same family (an artifact-trust refusal), documented in the updated header comment.

## What NOT to Try

- Do not add a third, redundant "once at start, once at end only" guard variant back in --
  the whole point of this phase is that per-run capture replaces that insufficient shape as the
  load-bearing signal (see the script's own updated header note).
- Do not assume `--regen-hints` can get PER-SUITE load granularity without instrumenting
  `tests/run-all.sh` itself -- that script is out of scope for Phase 1 (Phase 1's Files to
  modify list names only `measure-gate-costs.sh` and its own test suite), so per-run-all.sh-
  invocation granularity is the correct, deliberate scope boundary, not a shortfall.

## Critical Context

- Phase 4's root-cause work and every later phase's before/after measurement depend on this
  hardening; they should read an artifact's own `# ALL_VALID=` header before trusting any figure

- The host's ambient 1-minute load was ~5-6 during this phase's work (well above the 2.0
