## Current State

Phase 3 is `[COMPLETED]` in the plan, committed as one phase-end commit. A new library,
`agent-system/extensions/core/scripts/lib/gate-cache-lib.sh`, computes a composite,
content-addressed cache key per gate from two halves:
- **Corpus digest**: resolves a gate's declared `input_corpus` (Phase 2's grammar) against the
  filesystem (not `git ls-files`, for non-named-view entries -- see Deviations below) and hashes
  every resolved path's CURRENT working-tree bytes via `git hash-object`, folding sorted
  `path<NUL>blob` pairs into one digest. No mtime read anywhere.
- **Implementation digest**: five components -- the gate's own `verify-deploy.sh` invoke
  function body (text-extracted), every script/Lua-module it textually references, the ENTIRE
  `scripts/lib/*.sh` directory (a deliberate, documented, safe over-approximation of "every
  library the invoked script sources" -- see the library's own header for the full rationale),
  the gate's own registry row verbatim, and a literal source-store/deployed discriminator string.

Both halves return `GATE_CACHE_SENTINEL` ("CANNOT_COMPUTE") on any failure mode (undeclared
corpus, unresolvable entry, missing `git`, unreadable file) rather than an empty string, and a
separate `GATE_CACHE_EMPTY_CORPUS_DIGEST` constant distinguishes "declared, zero matches today"
from "not declared at all."

## Key Decisions Made

- **One code path for content addressing, not a tracked/untracked conditional**: every corpus
  path is hashed via `git hash-object <path>` against its CURRENT working-tree bytes,
  regardless of whether it is tracked, modified, or untracked. For an unmodified tracked file
  this reproduces the exact blob id the index already holds (same bytes, same algorithm), so one
  code path covers what the plan's Evidence section described as two cases.
- **Filesystem-based resolution for literal paths/bare directories/globs; git-based ONLY for
  `@extensions`/`@repo`**: this is a load-bearing correction to the plan's own framing (see
  Deviations) -- `.claude/**` is gitignored, so `git ls-files` can never see it, and several
  real corpus declarations (gates 1, 2, 9, 13, 16) point there.
  `find -path`'s `*` crosses directory separators (broader than a typical single-level shell
  glob); this is accepted deliberately as a safe over-match, consistent with the
  over-declaration-is-safe/under-declaration-is-not principle already established in Phase 2's
  own corpus-declaration notes.
- **Bounded sourced-library closure = "the whole `scripts/lib/*.sh` directory," not a precise
  per-script static trace**: every sourced-library line in this codebase sources via a variable
  built from the sourcing script's own resolved `SCRIPT_DIR`, not a literal path string, so a
  reliable per-script trace would need either executing the script (unsafe) or a real bash
  parser (out of scope). Over-inclusion here can only reduce skip-eligibility, never cause an
  under-declared miss.
- **`GATE_CACHE_RESOLVED_FILE`/`GATE_CACHE_UNRESOLVED` as direct out-parameters, never captured
  via `$(...)`**: a real bug (see Deviations) showed that a function's global-variable side
  effects do not survive a command-substitution subshell boundary.

## Deviations from Plan

The plan's own Files-to-modify/Tasks text is followed; no task was skipped or altered. Four
real implementation defects were found and corrected DURING this phase (recorded in
`progress/phase-3-progress.json`'s `approaches_tried`, repeated here because they are
load-bearing for anyone extending this library):
1. Resolving non-named-view corpus entries via `git ls-files` returns nothing for a gitignored
   path -- silently produced an empty corpus for every gate whose declaration points at the
   `.claude/` deploy tree (gates 1, 2, 9, 13, 16 at minimum). Fixed by resolving those three
   entry shapes against the filesystem directly.
2. `GATE_CACHE_UNRESOLVED` set inside a function called via command substitution never reached
   the caller (subshell variable scoping) -- gate 14's `-` corpus silently fell through to
   "zero matches" instead of the sentinel. Fixed via direct out-parameters.
3. A `PATH="$FAKEBIN"` (replace, not prepend) test for the missing-git-binary case broke every
   other coreutils tool too, producing a misleading result. Fixed by prepending.
4. The test suite's own `ROOT` path arithmetic was off by one directory level (3 "`..`" instead
   of 4 from the `scripts/` directory), causing several cases to silently exercise the wrong
   tree. Fixed.

None of these defects shipped to the committed state -- all four were caught and corrected
during this phase's own live testing, before the final test suite and library were committed.

## What NOT to Try

- Do not resolve a literal path, bare directory, or glob corpus entry via `git ls-files` -- it
  will silently miss everything under the gitignored `.claude/` tree. Only `@extensions` and
  `@repo` are git-based; everything else in the grammar is filesystem-based by design.
- Do not try to compute a PRECISE per-script transitive sourced-library closure by parsing
  variable-based `source "$VAR"` lines -- this was considered and rejected as unreliable without
  either executing the script or a real bash parser. The chosen bound ("the whole
  `scripts/lib/` directory") is a deliberate, safe simplification, not an oversight; do not
  "improve" it into a narrower-but-fragile per-script trace without re-deriving why the broad
  bound was chosen (see the library's own header).
- Do not capture `gate_cache_resolve_corpus`'s result via `$(...)` and expect
  `GATE_CACHE_UNRESOLVED` to be set correctly afterward -- call it directly and read the two
  global out-parameters.
