## Key Decisions Made

- The `--audit-verdict` match contract is keyed on `project_name` (not `project_number`), since
  the real number is rarely known at audit time (audits run before `--allocate-into` executes).
  This is a NEW convention this phase introduces; Phase 8's wiring must set each audited
  proposal's `id` field to the slug it is about to use.
- `--audit-override` and `--audit-verdict` may both be given; a verdict match wins (and is
  recorded) for any entry it covers, override only fills the gap for entries it doesn't.

## What NOT to Try

- Do not test the audit-evidence gate via `--state-file` pointing at a scratch file — the gate
  is deliberately scoped to the DEFAULT target only, so `--state-file` always bypasses it. Build
  a full fake-repo skeleton (`.claude/scripts/` + `specs/`) instead, as this phase's own
  verification did.
- Do not add `--audit-verdict`/`--audit-override` plumbing to any OTHER existing
  `--allocate-into` call site found failing unless its failure output actually names
  "audit-evidence" — the 5 unrelated failures above are NOT this gate's fault and must not be
  "fixed" by a change here.
