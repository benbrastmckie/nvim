## Deviations from Plan

- **Case (o)'s acceptance required a Phase 2 bug fix.** Writing the "first batch empty-filtered,
  second admissible" case surfaced that `mode_next_batch()` populated `READY_SET` by calling
  `build_ready_set()` inside a process-substitution subshell (`done < <(build_ready_pool)`), so
  the associative array never persisted back to the parent shell where `task_is_ready()` is
  later called — every roadmap batch was seen as empty-filtered regardless of real readiness.
  Fixed by calling `build_ready_set()` directly in `mode_next_batch()`'s own shell. Also added a
  visible `"Authored roadmap batch N: skipped"` line for an empty-filtered batch (Phase 2's
  implementation only recorded the skip in a counter). Both fixes landed in
  `orchestrate-suggest-next-batch.sh` during Phase 3 — beyond that phase's test-file-only Scope
  Hypothesis — recorded via `issue-record.sh` (`class: scope excursion`) rather than silently
  absorbed.
- **Verification-tooling gap**: `run-all.sh`/the test file's default subject-resolution mode
  silently tested the stale deployed tree in Phases 1-2 of this task. Recorded via
  `issue-record.sh` (`class: verification gap`). Both Phase 1 and Phase 2 were re-verified with
  the override during Phase 3 and found correct; no further rework was needed.
