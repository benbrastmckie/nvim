## Key Decisions Made

- `git_corpus_enum` is a drop-in replacement for the existing `git -C "$REPO_ROOT" ls-files
  "$enum_path"` call: identical newline-delimited, repo-root-relative output shape, so neither
  consuming script's scan-loop body needs to change -- only the enumeration line itself.
- `git_corpus_unenumerated_report` is a no-op for enum_path "." (repo-wide mode); callers invoke
  it only in PATH_SCOPE mode, per the plan's Non-Goals (no noise from the whole gitignored
  `.claude/` deploy tree on a repo-wide run).
- The Sibling Enumeration Audit's full narrative lives in the new library's own header comment
  (the single durable home), not duplicated into the inventory doc (that correction is Phase 4's
  job, and only for the `check-record-versioning.sh` entry).

## What NOT to Try

- Do not route `git_corpus_unenumerated_report`'s walk through `git_corpus_enum` plus a raw
  `find` diff for a *single-file* enum_path -- a single file's existence is checked directly
  (`[[ -f "$scope_dir" ]]`) rather than walked, since `find` on a file path still works but the
  directory-walk code path net was clearer kept as two branches.
