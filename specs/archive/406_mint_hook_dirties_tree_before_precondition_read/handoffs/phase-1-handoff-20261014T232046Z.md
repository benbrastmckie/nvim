## Key Decisions Made

- `pg_audit_flush` gates its fail-safe truncation on the `events-append.sh` helper's
  availability, checked ONCE before the drain loop, rather than on each individual
  `pg_events_append_observable` call's return value -- that wrapper's own contract always
  returns 0, so a per-call check could never distinguish success from failure. This coarse
  precondition still covers the dominant real failure mode (a missing/non-executable helper)
  and matches the posture already established by `pg_events_append_observable` itself.
- Buffer schema: `{event_type, category, message, session_id, detail, recorded_at}` one JSON
  object per line. `recorded_at` (mint/consume time) is merged into the flushed event's
  `detail` object at flush time; the flushed event's own top-level `timestamp` is assigned by
  `events-append.sh` at flush time, honestly.

## What NOT to Try

- Do not try to detect per-line append failure via `pg_events_append_observable`'s return

  later, call `events-append.sh` directly and check its real exit status instead.
- Do not use `git stash` in this shared/concurrent working tree (sibling tasks 403/404 are
  dispatched in this same orchestrate cycle) -- discovered this the hard way while trying to
  diff against HEAD; used a separate copy of the file instead.
