  `"[repo:<slug>] session capture via sapience-tag-pending.sh"` string; a non-empty one gets
  `" [repo:<slug>]"` appended.

## What NOT to Try

- Do not write the jq rewrite without `-c` (compact mode). The first draft of the `--write` path
  used `jq --arg p "$new_provenance" '.provenance = $p'` with no `-c`, which pretty-printed each
  rewritten record across multiple lines, breaking the ledger's one-JSON-object-per-line
  invariant and corrupting the file on a second pass (confirmed by a fixture test: a re-run
  reported "project=<none> unresolvable=24" instead of a clean idempotent no-op). Fixed by adding
  `-c`. Any future edit to that jq call must keep `-c`.
- Do not expect `test-manifest-scripts-sync.sh` to pass against a brand-new, uncommitted script
  file: it reads `git ls-files`, so an untracked new script reads as "declared but absent" until
  `git add`ed. This is not a real defect — `git add` the file before re-running that check.
- Do not retry the full, unnarrowed `run-all.sh` battery under batch contention expecting it to
  resolve quickly — in this dispatch it hit gate-lock contention (another session's stale lock
  reclaimed, load average 6.25) and an unrelated `[FAIL]`. The named checks
  (`test-manifest-scripts-sync.sh`, `test-script-inventory.sh`) run standalone in seconds and are
  the actual Phase 1 Tier Justification target; prefer those directly when the generic
  `--gate8-touched` narrowing falls back to the full-sweep sentinel because a brand-new,
  not-yet-tested file is among the touched paths.
