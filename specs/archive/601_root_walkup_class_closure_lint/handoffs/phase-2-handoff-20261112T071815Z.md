**Key Decisions Made**:
- Detection computes a per-file SAFE_LEVELS boundary (1 for a flat `scripts/*.sh` file, 2 for a
  `scripts/tests/*.sh` or `scripts/lint/*.sh` file) rather than a fixed "any 2+-level walk is
  forbidden" threshold -- the latter was tried first and found to false-positive on a real, safe,
  currently-live 2-level walk (`test-manage-topics-create-order.sh`'s `TREE_ROOT`) that correctly
  resolves the extension-root boundary (same relative depth in both trees), not the repo root.
- Anchor-offset tracking is intentionally bounded to `$SCRIPT_DIR` (offset 0) plus the single
  observed `NAME="$(cd "$SCRIPT_DIR/.." && pwd)"` idiom (offset 1, e.g. `CORE_DIR`). A walk
  anchored on any OTHER already-resolved root-like variable (e.g. `EXTENSIONS_ROOT`) is not
  tracked and not checked -- documented as a KNOWN LIMITATION in the script's own header, verified
  safe in every instance actually present in the live corpus (each such variable was itself
  produced by an already-guarded resolution and consumed only inside the branch that validated
  it).
- Guard (a) was generalized from "git-rev-parse-specific" to "any enclosing `if [[ -z "$VAR" ]]`
  fallback block, within 5 lines before the walk" -- both because the plan's own task bullet
  described the STRUCTURAL shape (an `if [[ -z "$VAR" ]]` block) as the sanctioned pattern, and
  because a git-specific regex false-positived against a real, safe, non-git ancestor-search
  fallback discovered during this phase's own corpus dry run (literature/test-lit-pipeline.sh).
- Guard (b) was extended beyond "same-line validated candidate" to also recognize an
  assign-then-validate-shortly-after variant (target tested within the next 8 lines) and a
  validate-then-assign-moments-ago variant (the identical literal string tested within the
  previous 3 lines) -- both real, observed shapes in sapience/test-sapience-capture.sh.
- Phase 2's own Verification block requires an unknown argument to exit 2; this deliberately
  diverges from the model lint's own looser "unrecognized token falls through as a path"
  behavior, per that explicit requirement.
