# Phase 3 Handoff: Wire ownership resolution into `manager.verify` / `manager.verify_all`

**Immediate Next Action**: Begin Phase 4 -- correct gate 16's warning hint text in
`agent-system/extensions/core/scripts/verify-deploy.sh` (source-store edit).

**Current State**: Phase 3 completed. Plan file is current (`[COMPLETED]` heading, all 5
checklist items `[x]`).

**Key Decisions Made**:
- Added a local `assemble_ordered_extensions(project_dir)` helper inside `manager`'s closure,
  mirroring `manager.find_orphans`'s existing assembly pattern (`list_loaded` ->
  `compute_deploy_order` -> `manifest_mod.get_extension` per name).
- `manager.verify_all` builds `assemble_ordered_extensions` + one `build_ownership_map` call, then
  loops `manager.list_loaded(project_dir)` (NOT the `extensions` array) to call `manager.verify`
  per name -- deliberately kept the original iteration source so a loaded name that
  `manifest_mod.get_extension` cannot resolve still surfaces its pre-existing "Extension not
  found" failure report, rather than being silently dropped by switching to the filtered
  `extensions` array.
- `manager.verify(extension_name, project_dir, ownership_map)` takes the map as a plain optional
  3rd positional argument (not a wrapped `opts` table) -- the existing 2-argument call form is
  unaffected; when the 3rd argument is omitted, `manager.verify` assembles the active set and
  builds its own map inline.

**Deviations from Plan**: None substantive. The plan's task bullet names the new parameter
`opts` in passing ("manager.verify(extension_name, project_dir, opts)... optional third
argument carrying the prebuilt ownership map") but today's real baseline signature is 2 positional
arguments with no existing `opts` table to extend -- implemented as a plain 3rd positional
`ownership_map` argument instead of introducing a new wrapper table, since the plan's own Goals
language ("the existing two-argument call form must keep working") and Verification bullets
describe exactly this behavior, not a specific wrapper shape.

**What NOT to Try**: Do not switch `manager.verify_all`'s result loop to iterate
`assemble_ordered_extensions`'s return value directly -- it silently drops any loaded extension
name `manifest_mod.get_extension` fails to resolve, changing `#results` and losing that
extension's failure report. Keep iterating `manager.list_loaded(project_dir)` for the loop; use
the ordered array only for `build_ownership_map`'s input.

**Verification performed** (direct headless calls):

  zero `VERIFY_FINDING` lines.
- `manager.verify('core', project_dir)` (2-arg, no map) returns `status=passed`, `errors=0`.
- A monkeypatch of `verify_mod.build_ownership_map` counting invocations during
  `manager.verify_all(project_dir)` confirms exactly 1 call (not 7).
