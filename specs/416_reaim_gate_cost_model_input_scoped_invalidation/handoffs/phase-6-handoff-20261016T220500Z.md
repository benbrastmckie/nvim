## Key Decisions Made

- **Stub `shellcheck` over live-process monitoring**: the natural first approach (sample real
  `shellcheck` process counts via a `kill -0`-loop with `pgrep -f`) is BLOCKED by this
  repository's own `validate-bounded-waiter.sh` PreToolUse hook, which refuses any Bash-tool
  command shaped as a liveness loop combined with a process-name match -- even when the match is
  used for sampling, not as the liveness test itself. A PATH-substituted stub binary sidesteps
  this entirely: no live polling, fully deterministic post-hoc log analysis.
- **Fixed 0.4s stub sleep, not a measured real-shellcheck duration**: gives a wide timing margin
  (shellcheck itself takes tens of ms on tiny files) so the dispatch-shape assertion is robust to
  host scheduling jitter without needing a tolerance band.
- **Reused the SAME 9-file fixture for both the dispatch-shape case (stub) and the equivalence
  case (real shellcheck)**: one fixture with 8 clean files + 1 seeded-violation file serves both
  purposes, since the stub ignores file content entirely.
- **Hint figure for `test-lint-shellcheck-parallel.sh` reflects the NEW cost (1971ms), not a
  blended or historical figure** -- the suite's default path genuinely costs ~2s now; the
  preserved real-corpus comparison is opt-in and does not run under `run-all.sh`'s default
  scheduling, so hinting it at the old ~120s figure would mis-schedule it.

## What NOT to Try

- Do not write a Bash-tool command combining a `kill -0 PID` liveness loop with `pgrep -f` or
  `ps | grep` for ANY purpose, including passive sampling/counting -- `validate-bounded-waiter.sh`
  blocks it outright regardless of intent. Use a self-logging stub/instrumented binary instead
  when you need to observe concurrent-process behavior deterministically.
- Do not re-introduce a batched (multi-file-per-invocation) shellcheck dispatch shape to
  "optimize" further -- this was measured and rejected during the original parallelization work
  (every batched shape was slower than one-process-per-file on this corpus), and the new
  dispatch-shape case's "every invocation names exactly one file" assertion will catch a
  regression toward it.
