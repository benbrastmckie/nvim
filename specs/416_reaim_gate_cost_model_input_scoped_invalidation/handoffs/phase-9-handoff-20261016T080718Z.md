## Key Decisions Made

- **Fixture is a `git worktree add --detach HEAD` checkout, not an rsync copy.** Shares this
  repo's object store (fast) while giving a genuine `.git` the `@extensions`/`@repo` named-view
  corpus resolvers can walk via `git ls-files` -- an rsync-copy fixture (the pattern
  `test-verify-deploy-gate-selection-crash-net.sh` already uses) gives those resolvers nothing to
  walk, since it is deliberately untracked.
- **`run_vd()` invokes the FIXTURE's OWN copy of `verify-deploy.sh` against itself (self-
  targeting), not the live repo's binary against a foreign target.** This is the one genuinely
  non-obvious finding of this phase's harness-debugging: `gate_cache_composite_key`'s "registry
  row" component is read from `${_VD_SCRIPT_DIR}/gate-registry.data` -- the RUNNING script's own
  directory, never `$TARGET`'s. In real usage script-dir and target are always the same tree, so
  this is invisible; cross-wiring them (as this suite's first draft did) makes editing the
  fixture's own registry invisible to the key, which looks exactly like "registry-row
  sensitivity is broken" when it is really a fixture-invocation mismatch.
- **Gate 8's `run-all.sh` is stubbed inside the fixture** (same precedent Phase 6 already
  established for `lint-shellcheck.sh` in `test-lint-shellcheck-parallel.sh`): the stub preserves
  `gate8_run`'s real invocation contract while swapping the expensive ~457s payload, so the cache
  WIRING around gate 8 is proven without paying run-all.sh's own real cost on every case.
- **Gate 22 (`lint-shellcheck.sh`) is excluded from both mechanical loops (Part 4's corpus-
  violation re-run, Part 6's registry-row sensitivity) after a FIRST version of this suite
  measured 604s total -- right at run-all.sh's 600s per-suite bound, with gate 22's own real
  ~54s cost repeated across 4+ invocations.** Gate 22's violation-DETECTION semantics are proven
  for real, once, by its own dedicated semantic case (Case G22); the two mechanical loops exist
  to prove the WIRING is gate-independent machinery, which the other 17 gates already establish.
  A second pass also scoped Part 7's realistic-sequence test to a small 9-gate subset
  (`SEQ_GATES`) rather than the full 18-gate `IFACE_GATES`, since that part's "full sweep" leg
  deliberately runs every included gate for real regardless of cache state. Final measured time:
  543s.
- **Gates 3, 16, 20 are proven at the composite-key level only**, each for a distinct, evidenced
  reason recorded in the suite's own header and in the plan's checklist annotations -- not a
  silent narrowing.

## What NOT to Try

- Do not invoke the LIVE repo's `verify-deploy.sh` against a separate fixture target for any
  cache-key-sensitivity test -- the registry-row component will not reflect fixture edits (see
  Key Decisions above). Self-target: invoke the fixture's own copy.
- Do not edit a registry row by inserting a byte directly after the id field (e.g.
  `s/^${g}\t/${g} \t/`) to test registry-row sensitivity -- `IFS=$'\t' read -r id ...` folds the
  inserted byte into the id field itself, silently breaking `--only-gate`'s exact-string
  `gate_selected()` match and making the gate SELF-SKIP (0 checks) rather than genuinely
  re-running, which looks like "still cached" in a naive SKIP-CACHED grep. Append at the line's
  END instead.
- Do not capture a `verify-deploy.sh` run via `$(...)` without `2>&1` when the assertion needs
  any `[FAIL]`-bearing text or the FAIL-shaped summary line's skip/check counts -- both are
  written to stderr by design (`fail()`'s own definition, and the `echo ... >&2` at the FAIL
  summary line). Every semantic case in a first draft of this suite silently lost this text.
- Do not include a gate whose own real cost is "slow" (today: 3, 8, 22) in a REPEATED loop
  (once per gate in the loop, times however many loops) without first checking whether that
  specific gate's property is already covered by a one-off dedicated case -- the aggregate cost
  of a slow gate repeated across several loops is what pushed this suite's first version past
  run-all.sh's own per-suite bound, not any one individual call.
- Do not seed a task-reference-lint test fixture string without checking whether the line you
  are writing (in THIS suite's own `.sh` source, authored via the Edit/Write tool) itself trips
  the repo's write-time `validate-no-task-references.sh` hook. If it does, wrap the authored
  LINE in a `task-ref-ok:begin`/`:end` block comment in the source file -- never add the
  `task-ref-ok` substring to the actual STRING WRITTEN to the runtime target file, since that
  marker text would travel into the fixture and exempt the very violation the case exists to
  seed.
