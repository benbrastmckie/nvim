## Key Decisions Made

- **Removed the second check-extension-docs.sh invocation entirely, rather than caching its
  result.** The dispatch's own fact 2 and 3 (summary line is a consumer interface; a skip
  landing on one side of a findings baseline is a correctness hole) argue against introducing
  ANY new cache/skip semantics inside a single gate's own implementation -- the clean fix was to
  notice the second invocation was mathematically redundant with the first, not to make it
  cheaper or cached.
- **Parallelized via real forked processes, not background bash jobs sharing the interpreter.**
  Matches the established "one-process-per-unit beats any batched shape" finding from gate 22's
  own rejected-alternatives history, and sidesteps any risk of global-variable races between
  concurrent checks (each subshell gets its own private copy of every mutated global; the parent
  never reads a subshell's copy back, only its captured stdout).
- **CED_JOBS defaults to 4, matching JOBS_CAP, rather than a separately-tuned number.** Measured
  jobs=8 regressing to 24.3s (worse than jobs=4's 13.8s) is independent confirmation that 4 is
  the right cap on this host for THIS kind of subprocess-heavy workload too, not a
  `run-all.sh`-specific constant.
- **Deferred gate-registry.data's cost_class/timeout_s update to Phase 13.** See Deviations.
