## Key Decisions Made

- Split the delta check into a side-effect-free core (`shared_path_delta_status`, returns a
  status word) and a reporting wrapper (`check_shared_path_not_stray`, calls pass/fail/info).
  Required because the first draft of the non-vacuousness self-test called the reporting
  wrapper directly, and its intentional "should fail" direction left a permanent `[FAIL]` in
  the suite's tally, which would fail the suite via `exit 1` even though the self-test was
  behaving correctly. Caught by re-running the suite before moving on — see Phase 3 progress
  file's `approaches_tried`.
- The non-vacuousness check was done two ways: a safe, suite-internal self-test against a
  `$WORKDIR`-confined simulated path (never touching the real shared path), plus one manual
  end-to-end check against the REAL `agent-system/extensions/core/tmp/` path (planted before
  the suite ran, confirmed loud-skip, removed afterward).

## Deviations from Plan

## What NOT to Try

- Do not let a self-test's intentionally-triggered "this should fail" branch call the suite's
  real `fail()` — route it through a side-effect-free status function instead, or the
  self-test will break the suite it is trying to validate.
