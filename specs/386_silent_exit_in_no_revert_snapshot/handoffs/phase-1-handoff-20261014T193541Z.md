## Key Decisions Made
- Built the 2000-entry SIGPIPE fixture via `git stash create "<msg>"` (distinct commit per
  differing message, same tree, no working-tree mutation needed per entry) plus a direct
  `git update-ref --create-reflog -m "<msg>" refs/stash "$sha" "$old"` append. This measured at
  ~12s wall-clock for 2000 entries, well under the plan's 1-minute gating threshold, so no
  opt-in env var was added. Discovered along the way: `git update-ref` with identical old==new
  SHA values is a silent no-op that does NOT append a reflog entry (first attempt using a single
  reused SHA produced only 1 stash entry regardless of loop count) -- the per-iteration distinct
  commit object (via a differing `git stash create` message) is what makes each `update-ref`
  call a real, loggable transition.
- Used the plan's prescribed `make_scoped_repo "yes"` fixture for both the held-lock case and
  its negative control, matching the plan text exactly.
