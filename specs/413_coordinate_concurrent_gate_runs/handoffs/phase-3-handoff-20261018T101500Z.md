## Key Decisions Made

- **Integration defect found and fixed**: `VERIFY_DEPLOY_NESTED` is exported unconditionally near
  the top of `verify-deploy.sh` (its own pre-existing self-nesting guard), so checking it
  directly inside `gate8_run()` always reads `"1"`. Fixed by capturing
  `VERIFY_DEPLOY_WAS_NESTED_AT_ENTRY` before that export and testing the captured value instead —
  mirroring `tests/run-all.sh`'s own `RUN_ALL_WAS_NESTED_AT_ENTRY` pattern from Phase 2. This is
  recorded in the plan body (Phase 3's own section, "Integration defect found and fixed"
  subsection) and must be called out in the implementation summary: it is a general hazard for
  wiring a gate-lock-shaped bracket into any script that carries its own unconditional
  nested-guard export, not specific to this one call site.
- To exercise the real Gate 8 bracket before Phase 7's formal redeploy (gate8_run() always
  resolves the DEPLOYED task-lock.sh), the three touched files were temporarily copied
  byte-identically into `.claude/scripts/`. Re-confirmed after testing: all three remain
  byte-identical between source store and deployed tree. Phase 7's `deploy-headless.sh` is still
  the authoritative deploy step; this was a transient verification aid, not a substitute.

## What NOT to Try

- Do not check `VERIFY_DEPLOY_NESTED` (or `RUN_ALL_NESTED`) directly inside a function that runs
  after that script's own top-level unconditional export of the same variable — always capture
  an `*_WAS_NESTED_AT_ENTRY` value before the export, as both call sites in this task now do.
