## Deviations from Plan

- W4's fixture changed from an absolute `/etc/passwd` pathspec to an in-repo permission-denied
  file (chmod 000). `/etc/passwd` would be reclassified as out-of-repository by Phase 2's V9 gate
  and dropped before `git add`, flipping W4's outcome from refuse-to-commit to commit-with-warning
  and defeating its purpose as a safety case pinned against exactly that gate. Verified the
  replacement produces the identical rc=2/"genuinely unstaged" outcome today.
- T16's assertion widened from `rc -eq 0` to `rc -eq 0 OR rc -eq 5`. Discovered a pre-existing,
  orthogonal defect: V8's intent snapshot uses `git hash-object` which follows a symlink and
  hashes the pointed-to file's content, while the committed blob for a symlink is the raw
  target-path string -- the two never match, so V8 false-positives (exit 5) on EVERY symlink this
  script commits, in-repo or out-of-repo target alike. Reproduced with an in-repo-target symlink
  to confirm it is unrelated to this task's own fix. Recorded as a `kind: issue` entry in
  `issues.jsonl` (class "pre-existing defect", severity minor) rather than fixed -- out of scope
  for this task, which does not touch V8's snapshot mechanism.

## What NOT to Try

  stay unaffected by V9 -- any real absolute path outside the repo will be reclassified once V9
