## Key Decisions Made
- A real defect was found and fixed while writing Case 5/Case 7: `skill_validate_task_artifacts`'s
  exit-0/1/2 regex branches, when the summary line does not match the expected counted shape
  (e.g. validate-artifact.sh's uncounted "[FAIL] File is empty: ..." exit-1 message), now fall
  back to `file_errors=1` instead of silently leaving the count at its initialized 0. This is an
  extension of D-B's own "never silently zero" mitigation applied to unrecognized exit-0/1/2
  shapes, not just the exit-3/4/5 default branch the plan named explicitly. Recorded here since
  it is a scope refinement beyond the plan's literal Phase 1 task list, discovered during Phase 4
  test authoring.
- `check-task-references.sh agent-system/extensions/core/scripts` passes on the new suite (0
  unexempted occurrences); two lines whose literal assertion text must contain "task 1" (because
  that is the literal text command-gate-out.sh emits) carry `task-ref-ok` inline markers citing
  the category-6 rationale (fixture pins a literal string the script under test emits).

## Deviations from Plan

  or skip of any planned item).

## What NOT to Try
- Do not name fixture metadata fields anything other than the literal `**Task**:` field name
  validate-artifact.sh's PLAN_METADATA requires — an earlier draft renamed it to avoid a
  perceived task-number-citation conflict and broke every "valid" fixture (missing required
  field triggered a spurious repair). The field name itself never matches TASK_PATTERN (no
  digits follow "Task" before the value), so no exemption was ever needed for it.
