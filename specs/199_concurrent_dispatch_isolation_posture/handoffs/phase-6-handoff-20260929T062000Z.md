## Key Decisions Made

- **The two REAL task_type string values the family predicate covers are `"lean4"` and
  `"cslib"`** — verified against `agent-system/extensions/lean/manifest.json` and
  `agent-system/extensions/cslib/manifest.json`'s own `task_type` fields. `"lean4"` ALSO appears
  as a `keyword_overrides` alias inside cslib's manifest (for auto-detecting `cslib` from task
  description keywords at `/task` creation time) — a completely separate mechanism this
  predicate does not touch; do not confuse the two when reading cslib's manifest.
- **The provisioning call happens BEFORE the `orchestrate-build-dispatch.sh` call**, inserted
  right after the `--focus` block in the live per-task loop, so `--worktree` can be added to
  `build_args` before that call. On failure it `continue`s WITHOUT releasing the task-lock
  acquired earlier in the same loop iteration — this deliberately mirrors the loop's ONLY other
  post-acquire failure branch (the pre-existing "orchestrate-build-dispatch.sh failed" deferral),
  not a new convention.
- **`--dry-run`'s row builder computes `isolation` via the SAME predicate call** but never calls
  `dispatch-worktree.sh` and always emits `worktree_path: null`, regardless of what `isolation`
  says — this is what makes "--dry-run provisions nothing" true while still surfacing the
  identical choice a live cycle would make.
- **Additivity for existing consumers was verified by direct reading, not assumed**: both
  `skill-orchestrate/SKILL.md`'s Move 2 and Move 3 read `dispatch[]` row fields exclusively via
  named `jq -r .field <<<"$row"` calls (never positional array indexing), and neither reads
  `.isolation`/`.worktree_path` today. `orchestrate-cycle-postflight.sh` receives discrete named
  arguments FROM Move 3 (not the row itself) and is therefore unaffected by this phase's own row
  change — but Phase 7 will need to thread the two new fields through as NEW arguments, since
  they don't reach postflight automatically just because they're in the row (see Immediate Next
  Action above).
- **Redeployed after this phase too.** Both scripts' deployed copies should be confirmed live
