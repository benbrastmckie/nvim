## Key Decisions Made

- **`release` strips `.claude/`/`.lake/` before `git worktree remove`.** Both are hardlink-cloned,
  untracked-by-construction in every worktree (never committed, never symlinked). Without
  stripping them first, a plain `git worktree remove` (no `--force`) would refuse EVERY release as
  "dirty" — there would be no such thing as a clean release. Stripping them first leaves only
  genuine uncommitted SOURCE edits (a real signal worth refusing on) to trigger git's own
  clean-check. Phase 5's `land` verb should assume this same asymmetry: dirtiness in `.claude/`/
  `.lake/` is expected and harmless; dirtiness in tracked source paths is the real signal.
- **`prune`'s "live session" test is the age-based staleness pattern, not a pid-liveness check.**
  A record naming the CALLING session (`--session <sid>`) is spared unconditionally regardless of
  age; every other record is reaped only once its `created_at` exceeds `DISPATCH_WORKTREE_STALE_SEC`
  (default 3600s). This matches the plan's own instruction to reuse
  `specs/.commit-lock/`/`task-lock.sh`'s staleness pattern rather than build a new liveness
  primitive.
- **`provision`'s idempotent-reuse check** matches on an existing registry record AND `git
  worktree list --porcelain` still recognizing the path — not the record alone (a crashed
  mid-provision could leave a record with no real worktree, which must NOT be treated as reusable).
- **manifest.json registration was necessary, not optional.** `deploy-headless.sh` ships only
  what `provides.scripts` names explicitly (no glob discovery) — a first deploy attempt during
  this phase's verification confirmed `dispatch-worktree.sh` was silently absent from `.claude/`
  (`RESULT=landed_verify_red`) until both new paths were added. Redeployed after the fix;
  `.claude/scripts/dispatch-worktree.sh --help` now works in this repo's own deployed tree.
  `check-extension-docs.sh` now reports `core PASS`. A separate, PRE-EXISTING, unrelated `literature`
  extension doc-lint failure (three orphaned zotero test/fixture scripts not in that extension's
  own manifest) remains — not touched, not in this task's scope, and was already present at
  dispatch start (visible in `git status` at conversation start as a modified
  `literature/index-entries.json`, most likely a concurrently-running sibling dispatch's in-flight
