## Deviations from Plan

- **Real defect found and fixed, not anticipated by the plan text**: the plan's own task
  pseudocode (`--only "$(IFS=,; echo "${_g8_suites[*]}")"`) didn't specify the exact array
  expansion form for the UNNARROWED invocation's optional args. Using
  `"${GATE8_ONLY_ARGS[@]:-}"` there is a real bug: confirmed by direct reproduction that bash's
  `:-` default form substitutes ONE empty-string word for a zero-element array (argc=1), not
  zero words, so every unnarrowed run was passing a spurious empty argument to `run-all.sh`,
  which rejected it with `exit 2`. Fixed by using the bare `"${GATE8_ONLY_ARGS[@]}"` form
  (confirmed argc=0 for an empty array under this file's `set -uo pipefail` on bash 5.3.9).
- A second, smaller defect: the plan's Phase 1 instruction to declare `GATE8_TOUCHED`'s default
  "beside the existing `GATE8_JOBS` declaration" is impossible as literally written, since that
  declaration site runs AFTER the argument-parsing while loop and would clobber the value the
  `--gate8-touched` case arm had just set. Fixed by declaring the default before the while loop
  instead (alongside `GATES_FILTER`/`JOBS`).
- Both deviations recorded in `issues.jsonl` via `issue-record.sh` and in
  `progress/phase-2-progress.json`'s `approaches_tried`.

## What NOT to Try

- Do not add a `:-` default to an array expansion that becomes a command-line ARGUMENT list
  under this file's `set -uo pipefail` -- it silently injects one empty-string argument for a
  zero-element array. The bare `[@]` form is correct and already proven safe on this file's bash
  version. (The pre-existing `GATE_RAN_LIST`/`GATE_DIRTY_LIST` `[@]:-` reads elsewhere in this
  file are fine ONLY because they are `for`-loop iterands, where a spurious empty-string
  iteration is harmless -- never generalize that idiom to an argument list.)
- Do not chase the full-battery (`--only-gate 8`, no `--gate8-touched`) exit-1 flakiness in this
  live repo as if it were a Phase 2 regression -- it is confirmed PRE-EXISTING (reproduced
  identically against the completely unmodified deployed `.claude/scripts/verify-deploy.sh`).
  Likely causes: `test-gate-cache-equivalence.sh`'s documented load-sensitivity, and/or
  `test-gate-lock.sh`'s own nested fixtures inheriting the real `GATE_MUTEX_HELD=1` a
  genuinely-top-level `gate8_run()` exports. Out of this task's scope.
