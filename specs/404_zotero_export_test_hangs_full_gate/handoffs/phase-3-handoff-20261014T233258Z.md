## Current State
Phase 3 completed. Both real generator invocation sites in
`agent-system/extensions/literature/scripts/tests/test-zotero-generate-export.sh`
(`run_export`'s call and `t_path3_itemtype`'s direct call) are now wrapped in
`timeout "$EXPORT_TIMEOUT"` (default 60s, override via $ZOTERO_EXPORT_TEST_TIMEOUT). A
shared `_check_rc124` helper (keyed off a new `CURRENT_SCENARIO` global set in the dispatch
loop) emits a loud, bound-naming FAIL on rc=124 and returns 1 so callers bail immediately. The
three scenarios whose own logic treats "RC != 0" as the happy path
(`loud-fail-transport`, `loud-fail-malformed`, `shrink-guard-blocks`) each gained an
explicit early-return guard on `RC -eq 124` so a hang is never misread as their own expected
clean-abort outcome. A new `timeout-guard-fires` scenario drives a deliberately stalled
`sleep 10` through the same `timeout` mechanism with a tiny 2s bound and PASSES only if rc=124
fires within the few-second ceiling it asserts on its own elapsed time. All 13 scenarios pass in
~12s wall time for the whole suite. A deliberate temporary experiment
(`ZOTERO_EXPORT_TEST_TIMEOUT=1` against `short-mid-page`) confirmed the real path is wrapped:
it produced the loud "exceeded the 1s wall-clock bound (timeout rc=124)" message (no committed
change from that experiment -- it was an env var override at invocation time only). Plan and
progress file are current.

## Key Decisions Made
- `_check_rc124` takes the bound and rc as explicit parameters rather than reading a global,
  so `timeout-guard-fires` (which deliberately uses a different, tiny bound) is NOT routed
  through it -- that scenario's pass condition is the OPPOSITE of the real sites' (rc=124 is
  success there), so reusing the same FAIL-on-124 helper there would have been wrong; it reuses
  only the `timeout` coreutil invocation shape, not the interpretation.
- Only the three scenarios the plan names by name got the explicit `RC -eq 124` early-return
  guard; the other `run_export`-based scenarios already treat any non-zero RC as failure, so a
  124 there would already correctly (if slightly redundantly) report a FAIL via their own logic.
