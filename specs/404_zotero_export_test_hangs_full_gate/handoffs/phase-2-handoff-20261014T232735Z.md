## Key Decisions Made

- On bulk-jq failure, the function returns 1 with nothing on stdout (never `echo "[]"`) so the
  call site's `FINAL_COUNT` guard aborts loudly with no write.

## What NOT to Try
- Do not reach for `jq -r` per field followed by bash string comparisons the way the original
  loop did -- the whole point of the rewrite is one jq process for the whole array. The bulk
  jq script's `norm_key` function (null -> "", else tostring) reproduces the exact same
  "empty or literal string 'null' means absent" semantics the original bash comparisons encoded.
