**Immediate Next Action**: Proceed to Phase 2 — document the `OUTCOME:` line and the settled
layout ruling in `agent-system/extensions/core/context/formats/roadmap-format.md` and

**Current State**: Phase 1 completed and committed. Plan and progress file are current.
`write_or_diff` in `agent-system/extensions/core/scripts/roadmap-integration.sh` now emits a
named `OUTCOME:` stderr line on both `--regenerate` and `--prune`, before the frozen
`<!-- roadmap-generation ... -->` marker. `ROADMAP_LAYOUT` is set by `mode_regenerate`/
`mode_prune` immediately after `detect_layout` and consumed by `write_or_diff`.
`test-roadmap-generation.sh` baseline was 93 passing cases before this phase; 105 passing, 0
failing after (12 new cases, not the plan's hypothesized 7).

**Key Decisions Made**:
- The `OUTCOME:` line is emitted unconditionally from `write_or_diff` for both real writes and
  `--dry-run`, using `cmp -s` against the already-materialized staging file (no extra read).
- Four literal shapes exactly as specified in the plan, substituting `--${MODE}` and
  `layout=${ROADMAP_LAYOUT}`.
- The absent-roadmap no-op and the unrecognised-layout refusal both return before
  `write_or_diff` is reached, so neither emits an `OUTCOME:` line — confirmed by new tests, not
  just left alone by omission.

**Deviations from Plan**: None. The new test-case count (12) exceeded the plan's own stated
hypothesis of ~7; the plan explicitly asked for the actual count to be reported rather than
7 adopted silently, which this handoff and the plan checklist annotation both do.

**What NOT to Try**: Do not add a field to the frozen six-field marker — `roadmap-format.md`
freezes its shape; the `OUTCOME:` line is a separate, additional stderr line by design.
