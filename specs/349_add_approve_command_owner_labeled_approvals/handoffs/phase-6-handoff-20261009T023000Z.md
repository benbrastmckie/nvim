## Key Decisions Made

- **`--check-freshness` scope, stated plainly**: it compares the git short-HEAD the review was
  generated at (captured verbatim in the classification sidecar) against the CURRENT git
  short-HEAD of the repo the guard runs in. It does NOT recompute a Lean digest -- that logic
  lives inside `approve.sh`'s own private scratch state and is explicitly out of scope to
  duplicate. This is a coarse, cheap, HONEST backstop in front of `approve.sh --record`'s own
  fine-grained per-item digest re-check, which remains the authoritative one (confirmed by
  reading `components/framed_channel/approve.sh` lines ~416-427 in
  `~/Projects/Logos/Verification`: `--record` already refuses "the review again" when any
  `spec_yes` item's current digest no longer matches the review's recorded one).
- **`--check-labels`'s `(agent)` suffix regex** (`\(agent\)[[:space:]]*\<[^\>]*\>[[:space:]]*$`)
  mirrors the real `check-approvals.sh`'s own `assisted_by_matches`/`check_by` convention,
  confirmed by reading that script directly
  (`~/Projects/Logos/Verification/components/framed_channel/scripts/check-approvals.sh`).
- **`--presented` sidecar discrepancies contract** (consumed by `--check-surfaced`): a JSON
  object with a `discrepancies` array of item ids. Phase 7's `skill-approve` must write this
  shape when it builds the presented sidecar.
