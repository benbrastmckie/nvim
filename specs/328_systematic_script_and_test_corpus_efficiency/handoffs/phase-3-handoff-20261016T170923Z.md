  NET-TEST until `git add` is run. Confirmed directly: the probe reported `lines=90568`
  (unchanged) with the new lib untracked, and `lines=90661` (the correct, expected figure) once
  `git add`ed. Any later phase creating a file must stage it before trusting the probe's delta,
  or measure post-commit.

## What NOT to Try

- Do not scope a "no lint file still carries pattern X" regression assertion to the whole
  `scripts/lint/` directory when only SOME cluster members have been migrated in the current
  phase — the untouched siblings will false-positive. Scope to the exact migrated-file list.
- Do not grep for a function's own definition signature without anchoring to line-start when the
  search also recurses into the test file that necessarily quotes that same signature string as
  part of its own assertion code.
- Do not trust `script-inventory.sh --size-line`'s NET-PROD/NET-TEST figure for a phase that
  created a new file without first `git add`ing it (see Key Decisions above) — or trust the
  measured delta from `wc -l` arithmetic directly instead, which is unaffected by git tracking
  state.
