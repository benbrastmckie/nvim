## What NOT to Try

- Do not rely on `tests/test-script-inventory.sh` (or any suite) resolving the SOURCE-STORE copy
  of a tool it tests by default — its own documented convention is deploy-tree-first resolution
  (prefers `.claude/scripts/<name>.sh` over the source-store copy when the deployed copy exists).
  After any source-store edit to a script covered by such a suite, re-run
  `bash agent-system/extensions/core/scripts/deploy-headless.sh .` (resync mode, non-destructive,
  ~170s) BEFORE trusting a local suite run — otherwise you are silently testing stale deployed
  code and will see spurious failures (or spurious passes) that look like regressions.
- Do not assume this environment runs with `errexit` off just because a script's own `set -uo
  pipefail` line omits `-e`. `SHELLOPTS` is inherited from this harness's invoking shell with
  `errexit` already active, so a bare `var="$(failing_cmd)"` assignment kills the whole script
  immediately. Wrap any command expected to possibly exit non-zero in `set +e ... set -e
  2>/dev/null || true`, matching this suite's own existing convention (see the `--check`
  manifest-drift and usage-error blocks in `test-script-inventory.sh` for the pattern).
- Two pre-existing, unrelated verify-deploy findings were observed during this phase's deploy
  syncs and are NOT this task's concern: (1) doc-lint Rule S on
  `agent-system/extensions/lean/context/project/lean4/patterns/measurement-harness-strictness.md`
  missing an index.json entry, and (2) the eager-load total (67,088 B) exceeding its recorded
  baseline (66,100 B) for `commands/orchestrate.md`/`skill-orchestrate/SKILL.md`. Both predate
  this task's edits and are from concurrent in-flight work elsewhere in the repo. Recorded as a
