## Key Decisions Made
1. `--class`/`--tag`/`--cost-class` are three independent, comma-separated, opt-in axes that
   compose with `--only` AND with each other by INTERSECTION, never union across axes (union only
   within one axis's own comma list). An empty intersection is reported as run-all.sh's existing
   "zero suites discovered" harness failure (exit 2), never a silently empty partial run.
2. Zero new per-suite hand-authoring: `--class` reads the existing `suite-classification.data`
   column (from Phase 12); `--tag` is MECHANICALLY derived from that same file's `invokes:X[,Y]`
   reason tokens (stripped of `.sh`) plus a fixed `lint` tag for every `test-lint-*.sh` basename;
   `--cost-class` buckets the existing `suite-cost-hints.txt` wall_ms column at fixed thresholds
   (free &lt;2000ms, moderate &lt;30000ms, else slow; `unknown` for an unhinted suite). This was a
   deliberate rejection of hand-authoring a new tag column across 203 rows (see progress file's
   `approaches_tried`) -- the task's own net-deletion charter makes a bulk hand-authored retrofit
   the wrong default.
3. The new selection logic lives in `scripts/lib/suite-selection-lib.sh` as six new, additive
   functions (`suite_selection_known_classes`/`_tags`/`_cost_classes`,
   `suite_selection_by_class`/`_tag`/`_cost_class`), sourced from `run-all.sh` ONLY when one of the
   three new flags is given -- every pre-existing function and the `__FULL_SWEEP__` sentinel are
   untouched.
4. The Tier Justification's own literal command (`verify-deploy.sh --skip-slow --only-gate 8`) is
   a documented no-op (SKIP) -- `--skip-slow` defers gate 8 entirely. Real coverage came from a
   direct, unbounded `verify-deploy.sh --only-gate 8 .` and a direct `run-all.sh --quiet`
   full-battery run instead; see Critical Context below for the result and why it was judged
   sufficient despite 7 reported failures.

## What NOT to Try
1. Trusting the Tier Justification's literal `--skip-slow --only-gate 8` command as evidence of
   anything beyond "the flag combination is accepted" -- it SKIPs by design and proves nothing
   about gate 8's actual suite battery.
2. Re-deriving a bulk `suite-tags.data`-style hand-authored tag file for the whole corpus --
   already considered and rejected (see progress file). The mechanical derivation from
   `suite-classification.data`'s existing `reason` column is the intended, zero-authoring design.
3. Treating a future transient gate10 (`validate-state.sh --deep`) or orchestrate-cycle-fixture
   failure under this session's host contention as a regression without first checking whether
   the failing suite references ANY file this phase touched -- it almost certainly does not (see
   Critical Context).
