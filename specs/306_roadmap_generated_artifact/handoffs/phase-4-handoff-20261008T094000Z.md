## Key Decisions Made (bugs found and fixed during this phase)

1. **"IN FLIGHT" token mis-split.** `parse_retention`'s original `read -r num tok desc <<<
   "$rest"` assumed every status token is one word; "IN FLIGHT" has a space, so `tok` captured
   only "IN" and `desc` gained a stray leading "FLIGHT ". Fixed with an explicit two-word-token
   case (`[[ "$rest2" == "IN FLIGHT"[[:space:]]* ]]`) before falling back to the generic
   single-word split.
2. **Open work trailer dropped, then mis-joined.** First found via `--regenerate --dry-run`
   against the real live file: the free-standing `**342's hold**: ...` paragraph after the last
   fenced block was silently discarded by a regenerate (the whole `## Open work` body was being
   rebuilt from fenced blocks only). Added `extract_open_work_trailer` + documented the mechanism
   in `roadmap-format.md`. The first fix still produced a missing blank line between the last
   `` ``` `` and the trailer (concatenation math: both sides contributed only one of the two
   needed newlines) — fixed by adding the second explicit `$'\n'` separator.
3. **Reassembly strategy**: implemented as full-file reconstruction from nine extracted/rendered
   section bodies (`assemble_roadmap`), not literal in-place line-splicing of the original file.
   Behaviorally equivalent for byte-identical retention (every authored section's body is
   captured verbatim and re-emitted unchanged) and far simpler to test — recorded as a deviation
   from the plan's literal "section replacement...mirroring generate-task-order.sh's awk
   approach" wording, though the net effect (replace only the generated sections, leave authored
   ones byte-identical) is the same.
4. **`--prune`'s Next-line rewrite was initially too aggressive**: it reconstructed every
   `/orchestrate` line's text even when nothing was dropped from it, losing the original column
   alignment on unaffected lines. Fixed so a Run line is only rewritten when its task list
   actually shrinks; an unaffected line now passes through byte-identical.

## What NOT to Try

- Do not assume every status token is a single word when parsing an existing task line — "IN
  FLIGHT" is the one two-word exception in the closed vocabulary.
- Do not rebuild a `## Next` Run line's text unconditionally during `--prune` — only rewrite a
  line whose task list actually changed; an unaffected line must stay byte-identical, including
  its original spacing.
- Do not trust a `--regenerate --dry-run` test that only diffs against the hunk boundaries
  reported by `diff` — a missing blank line or a free-floating authored paragraph can hide
  inside what looks like unchanged context; `grep -n '<text>' -B2` the actual file with `cat -A`
  to be sure, as this phase's own earlier false-confidence moment showed.
