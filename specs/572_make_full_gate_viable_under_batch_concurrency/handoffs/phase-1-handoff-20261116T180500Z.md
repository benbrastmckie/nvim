## Key Decisions Made

- The directive's phase-list wording uses correct singular/plural grammar ("Phase 2 of the plan
  declares" vs. "Phases 2, 4 of the plan declare") rather than an informal "Phase(s)" shorthand.
- The phase-number list join uses `printf '%s, ' ... | sed/strip trailing`, not an
  `IFS=', '; "${arr[*]}"` expansion — the latter uses only IFS's first character as the join
  separator and silently collapses `", "` to `","`. Caught by a manual smoke test before writing
  the automated suite cases.
- `phase-heading-patterns.sh` is sourced directly via `${SCRIPT_DIR}/lib/phase-heading-patterns.sh`
  (a plain sibling-directory resolution) rather than the dual deployed/source-store candidate

  this script's own `BASH_SOURCE`, so the sibling `lib/` directory resolves correctly whether this
  script is running from `.claude/scripts/` (deployed) or `agent-system/extensions/core/scripts/`
  (source store); no dual-candidate list was needed.

## What NOT to Try

- Do not use `IFS=', '; "${arr[*]}"` for a multi-character join separator in bash — it only uses
  the first IFS character. Use the `printf '%s, ' ... | strip trailing ", "` idiom instead (already
  in place in `orchestrate-build-dispatch.sh`'s new scan block).
