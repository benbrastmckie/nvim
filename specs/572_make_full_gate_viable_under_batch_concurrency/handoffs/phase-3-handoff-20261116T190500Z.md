## What NOT to Try

- Do not smoke-test `gate8_run()`'s contention logic by repeatedly invoking the full
  `verify-deploy.sh --only-gate 8` against the real repo without a disciplined bounded wait on
  the EXACT captured PID each time. Doing so here left 4+ overlapping invocations running
  concurrently (each contending for `specs/.gate-lock`) after the harness auto-backgrounded
  several foreground calls at its ~180s mark. Cleaned up via `SIGTERM` (the Phase 3 signal-scoped
  trap released the mutex correctly — no stale lock was left behind). Prefer an isolated,
  logic-only extraction test (source just the two new functions via `awk`, feed them fixed env
  overrides) for iterating on the trigger math, and reserve the real fixture-backed
  `test-gate-lock.sh` suite (run once, bounded) for the actual verification.
- Do not run `generate-context-line-counts.sh` from the deployed `.claude/scripts/` copy expecting
  it to update the source store — always `REPO_ROOT=$(pwd) bash
  agent-system/extensions/core/scripts/generate-context-line-counts.sh --write` from the
  source-store tree.
