  documented containment sites (`context/standards/git-staging-scope.md`'s "Three Containment
  sites, not one" section). This phase patches only Site 2 (`git-commit-phase.sh`'s own
  Containment Self-Check). Site 3 (`git-commit-scoped.sh`'s separate V10 guard, which independently

  carries the identical latent loophole for a `.claude/`-only declared `file_scope`. This was
  discovered via the Case 26 fixture: when `file_scope` is solely `.claude/`, Site 2 correctly
  fails open (skips itself entirely), but Site 3 still runs its own (un-patched)
  `is_contained_v10()` against the unstripped `.claude/` entry and can still drop an otherwise
  legitimate `files_touched` path. A full architectural closure would need the same deployed-tree
  strip ported to `git-commit-scoped.sh`'s V10 `containment_scope_arr` resolution block — out of
  this task's declared `file_scope`, so not done here. Phase 5 (updating
  `git-staging-scope.md`'s "Three Containment sites" section) should state this residual
  explicitly rather than implying full closure across all three sites.
- Case 25's fixture is the one that actually proves the Hard Constraint's named loophole closed:
  a bare `.claude/` `file_scope` entry previously caused `is_contained()`'s own entry-normalization
  (`"$entry%/"` stripped to `.claude`, then matched via `"$entry"/*`) to wrongly admit every
  `.claude/**` path. The strip now removes that entry before `is_contained()` is even built.
