## High Priority Issues

### CLAUDE.md standards pointers resolve to a non-existent path

**File**: `CLAUDE.md:30-36`
**Description**: The "Documentation Policy", "Box Drawing", and "Character Encoding and Emoji
Policy" sections point to
`.claude/extensions/nvim/context/project/neovim/standards/{documentation-policy,box-drawing-guide,emoji-policy}.md`,
and the "Lua Testing Assertion Patterns" line under Testing Protocols points to
`.claude/extensions/nvim/context/project/neovim/standards/lua-assertion-patterns.md`. None of
these four paths exist. The actual deployed files live one level up the tree, at
`.claude/context/project/neovim/standards/*.md` (confirmed present) — `.claude/extensions/nvim/`
is the extension's own manifest/source directory, not the deploy-context path these sections mean
to reference.
**Impact**: Every command whose context-discovery step follows these pointers (`/document`,
`/plan`, `/test`, `/test-all`, `/implement` per the `[Used by: ...]` annotations on each section)
resolves to a dead path instead of the real standard. The actual content is present and correct —
only the four pointers in the root `CLAUDE.md` are wrong.
**Recommended fix**: Change the four paths in `CLAUDE.md` from
`.claude/extensions/nvim/context/project/neovim/standards/...` to
`.claude/context/project/neovim/standards/...`.

## Medium Priority Issues

### Half of active keymaps are missing `desc`

**File**: multiple (see list below)
**Description**: CLAUDE.md's own Lua Code Style standard requires `vim.keymap.set` with
"descriptive options", and the Neovim extension's Common Operations section states "Use
`vim.keymap.set` with description for all keymaps." Of 88 `vim.keymap.set(...)` calls in active
(non-deprecated) code, 44 (50%) have no `desc` field. Affected files: `util/notifications.lua`
(4), `util/url.lua` (1), `config/notifications.lua` (2), `config/autocmds.lua` (1),
`config/keymaps.lua` (1), `plugins/tools/luasnip.lua` (2), `plugins/tools/autopairs.lua` (1),
`plugins/tools/mail.lua` (1), `plugins/tools/himalaya/data/templates.lua` (4),
`plugins/tools/himalaya/data/search.lua` (2), `plugins/tools/himalaya/ui/features.lua` (10),
`plugins/ui/neo-tree.lua` (8), `plugins/ai/shared/extensions/picker.lua` (2).
**Impact**: Reduces discoverability via `which-key`/`:map` introspection and conflicts with the
project's own documented standard.
**Recommended fix**: Add a `desc` field to each flagged keymap. `plugins/tools/himalaya/ui/features.lua`
and `plugins/ui/neo-tree.lua` account for 18 of the 44 and are the highest-value starting point.

### `init.lua.backup` is a stale, tracked duplicate of `init.lua`

**File**: `init.lua.backup`
**Description**: `init.lua.backup` is byte-identical to `init.lua` and has been tracked in git
since task 516/518 (an old pre-vault task numbering, well before the current ~293 range). It sits
at the repo root alongside the real `init.lua`.
**Impact**: Dead weight that invites confusion about which file is authoritative; a future edit to
`init.lua` with no matching edit to the backup silently reintroduces drift between the two.
**Recommended fix**: Delete `init.lua.backup` (git history already preserves prior states of
`init.lua`), or if a backup convention is intentional, add it to `.gitignore` instead of tracking
it.

### `project-overview.md` still carries the generic template notice

**File**: `.claude/context/repo/project-overview.md`
**Description**: The file still opens with the `<!-- GENERIC TEMPLATE -->` notice that
`.claude/CLAUDE.md` itself documents as the "new repository" signal ("If project-overview.md
doesn't exist or contains the generic template notice ... run `/project-overview`"). This repo is
not new — `specs/archive/` holds 200+ completed task directories.
**Impact**: Any command or agent that reads this file for repo orientation gets generic
boilerplate instead of an actual description of this repo's structure.
**Recommended fix**: Run `/project-overview` to generate a repo-specific version, then add
`context/repo/project-overview.md` to `.syncprotect` as the file's own header instructs.
