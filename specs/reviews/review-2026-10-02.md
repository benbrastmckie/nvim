## Medium Priority Issues

### Orphan detector false-positives on `.claude/scheduled_tasks.lock`

**File**: `lua/neotex/plugins/ai/shared/extensions/verify.lua:869-884` (`is_runtime_artifact()`)
**Description**: `.claude/scheduled_tasks.lock` is a session-acquired runtime lock file — its
contents are a live session's own `sessionId`, `pid` and `acquiredAt` — created at execution time
by the scheduled-task mechanism and never by the copy engine. That is precisely the class
`is_runtime_artifact()` already whitelists for `tmp/workflow-active-*`, `RESUME.md`,
`__pycache__/` and the literature venv, but no pattern matches it, so gate 13 (whole-tree orphan
detection) flags it as an undeclared orphan.

**Impact**: A reproducible false-positive `verify-deploy.sh` failure — the other half of today's
"FAIL 2 of 33" — that fires any time a scheduled or cron agent task has run before the gate. It
turns a healthy deploy red for no real defect, which is the failure mode that trains readers to
stop believing the gate. Disclosed for honesty: the lock file present during this review was
created at 14:29 by *this review session's own* scheduled wakeups, so this pass both triggered and
observed the condition.

**Recommended fix**: Add a pattern for `scheduled_tasks.lock` to `is_runtime_artifact()` (and
check for sibling lock files in `.claude/` while there), then register it in the
exclusion-classes table in `context/patterns/deploy-orphan-detection.md` so the whitelist and its
documentation stay in step.

4. **`state.json`'s `active_goal` was refreshed during this review** — it had described three
   resolved gates and a layer that no longer exists. Doing so surfaced a genuine defect, stated
   here as measured rather than as first assumed: **a rendered `**Goal**:` line in `TODO.md` cannot
   survive regeneration, and fails state validation while present.**
   `generate-task-order.sh --goal` writes the line, but `generate-todo.sh` drops it entirely and
   reads `active_goal` from `state.json` not at all — so the two generators disagree, and a
   `TODO.md` carrying the line is reported `OUT OF SYNC with specs/state.json` by
   `validate-state.sh --deep` (observed directly: 17 passed / 2 warnings / **1 failed**, recovering
   to 18 / 2 / 0 once the line was dropped). Net effect: `active_goal` is write-only and the
   displayed goal is permanently blank, which is why `TODO.md` carried no `**Goal**:` line to begin
   with. The field now holds the correct text and `TODO.md` is left in the only state that
   validates. Recorded as the leading entry under `ROADMAP.md`'s Unfiled observations; it belongs
   with the 306/308 automation chain.
