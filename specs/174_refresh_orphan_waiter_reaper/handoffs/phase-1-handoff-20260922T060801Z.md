**Key Decisions Made**:
- The fail-closed warning message (`build_self_exclusion_set` returning non-zero) deliberately
  omits the literal `$$` pid value in its text. Embedding it broke the pre-existing zombie-pass
  assertion (h) in the test suite, which asserts `--dry-run` and `--force` output are identical
  modulo the `[DRY RUN]` banner -- each subprocess invocation naturally has a different pid, so
  interpolating it made the two captured outputs diverge on that one line. This surfaced only
  because the build-waiter pass's own `ps -eo` call falls through the existing zombie fake `ps`
  fixture's default (empty) branch, driving the fail-closed path on every existing e2e assertion
  that doesn't provide a dedicated build-waiter fixture -- Phase 2 will replace this generic
  empty-fallthrough behavior with a dedicated "no rows for the pgid field spec" branch across all
  five existing fake `ps` fixtures, per the plan's Scope Hypothesis, and will exercise the
  fail-closed path deliberately as its own dedicated assertion.
- `build_waiter_row_is_idle()` was written as its own small function (not a direct call to
  `lean_row_is_idle()`), since it needs a caller-supplied threshold
  (`BUILD_WAITER_REAP_MIN`/`BUILD_WAITER_CEILING_MIN`) rather than the Lean pass's fixed
  `LEAN_LSP_IDLE_THRESHOLD_MIN` env var. It reuses the same integer-truncation idiom.
- The Family-A ceiling check compares `etimes` directly against `BUILD_WAITER_CEILING_MIN * 60`
  (seconds) rather than calling `build_waiter_row_is_idle()` a second time with the ceiling
  threshold -- functionally equivalent (pcpu==0 was already established) but reads closer to the
  plan's literal wording ("etimes >= BUILD_WAITER_CEILING_MIN").
- Every occurrence of the literal substring "pgrep" was removed from the new pass's comments
  (including the top-of-file header addition) and rephrased as "name-substring process search",
  since Phase 1's own verification step is `grep -n 'pgrep' claude-refresh.sh` finding no
  occurrence inside the new pass block, and it was simpler/safer to eliminate the token everywhere
  in the new material than to reason precisely about sed-range scoping.
