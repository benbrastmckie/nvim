**Key Decisions Made**:
- **Found and fixed a real Phase 1 bug**: `build_waiter_family()` was originally called as
  `family=$(build_waiter_family "$args")`, but command substitution always forks a subshell, so
  the function's `BUILD_WAITER_EMBEDDED_PID="${BASH_REMATCH[1]}"` side effect was silently
  discarded every time -- `run_build_waiter_pass()` would have always read a stale/empty embedded
  pid, breaking Family A's dead/live-writer distinction entirely in production. Fixed by having
  `build_waiter_family()` set two globals (`BUILD_WAITER_FAMILY` and `BUILD_WAITER_EMBEDDED_PID`)
  and having the caller invoke it as a plain statement (`build_waiter_family "$args"`, then read
  `$BUILD_WAITER_FAMILY`) in the same shell, never via `$(...)`. This is documented inline in the
  function's own header comment so it is not "fixed" back to the subshell-losing form later.
- The plan's instruction to "drive the dead/live embedded-PID cases through the overridable
  `_pid_is_alive` seam, as assertion (c) does" is satisfied via a different-but-equivalent
  mechanism for this END-TO-END case than assertion (c)'s UNIT-level technique: assertion (c)
  overrides the `_pid_is_alive` function definition directly in the same shell (valid only when
  calling functions directly, not through a subprocess). This end-to-end case instead runs the
  full script as a subprocess (needed for `main`'s argument parsing and the fake-`ps` snapshot),
  so it uses the `enable -n kill` + fake-`kill`-on-PATH idiom assertion (g)'s Lean ordering test
  already established for exactly this situation -- `_pid_is_alive`'s unmodified production body
  (`kill -0 "$1" 2>/dev/null`) reaches the fake `kill`, so the seam IS exercised, just via a
  different substitution point appropriate to a full-subprocess run. No real backgrounded process
  is spawned either way.
- The ancestor-exclusion test row uses the reaper's own REAL parent pid (`self_ppid`, one hop
  up), not a fabricated arbitrary pid, and not a two-hop grandparent -- `build_self_exclusion_set`'s
  ancestor walk only advances through rows PRESENT in the snapshot, so a hop the snapshot has no
  row for stops the walk early. See `progress/phase-2-progress.json`'s `approaches_tried` for the
  two design iterations this went through.
- The self-pid-discovery marker in the build-waiter fake `ps` is a FIXED literal string
  (`BUILDWAITER_HARNESS_SELFMARK`) embedded in every invocation's `bash -c` script body, not the
  (d-2) fixture's technique of matching the sourced script's own filename in argv -- the mutation
  checks source a MUTANT COPY at a different filename, which broke the filename-matching approach
  (see `approaches_tried`).
