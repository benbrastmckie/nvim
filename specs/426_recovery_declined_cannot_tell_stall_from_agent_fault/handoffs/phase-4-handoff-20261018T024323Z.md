## Key Decisions Made
- Fixture (J3) uses the MULTI-TASK engine (no --loop-guard-file), not the single-task engine
  the other RECOVERY_DECLINED fixtures use. Discovered that WORK (b)'s unconditional
  orchestrate-loop-guard-init.sh --clear-pending call rewrites any pre-existing
  .orchestrator-loop-guard file early in every postflight invocation, which defeats
  dispatch-strand-probe.sh's artifact-quiescence leg regardless of backdating. This is a
  structural property of the production script (not specific to this task's own changes) and
  is filed as its own minor follow-up issue in this task's issues.jsonl, matching T1's own
  precondition (T1 also omits --loop-guard-file for exactly this reason).
- VERIFY(4)'s lexical pin is scoped to each canonical field's own few-line block (via
  `sed -n '/^X=false$/,+6p'`) rather than a bare whole-file grep, because Phase 3's own
  rd_stall_* computation deliberately reuses the identical stall conjunction text at the record
  site (as the plan directed), which a whole-file "exactly once" grep cannot distinguish from an
  actual widening.
- Fixed a jq `//` pitfall in the J1/J2/J3 tag assertions: `.tags.X // "MISSING"` returns
  "MISSING" for a genuinely-false X (jq's `//` treats boolean false the same as null/absent).
  Switched to `if (.tags|has("X")) then (.tags.X|tostring) else "MISSING" end`.
