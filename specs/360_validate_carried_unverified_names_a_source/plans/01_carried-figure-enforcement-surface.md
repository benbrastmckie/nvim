## Overview

This plan builds the first mechanical surface for the `## Carried-Figure Discipline` convention
and then widens the convention itself, in the order the folded records' own dependency edges
already encoded. Part one is a narrow, advisory-only well-formedness check in
`scripts/validate-artifact.sh`: every mark of the fixed literal token in a report or plan
artifact must name a non-empty source designator. Part two widens the obligation to a
recommendation that asserts a measurable property of the live corpus, and to the premise a
dispatch acts on without restating. Part three requires a self-derived enumeration to state and
stress-test its search pattern, and states the verification-independence rule that today has no
home anywhere.

Nine phases rather than the usual four-to-six, because three originally-separate records were
consolidated into this one and every one of them writes the same two contract files plus the same
validator and its fixture suite. The phase count buys phases that each stay inside the two-hour
ceiling; it does not buy parallelism, and no parallelism is available here by design (see
Dependency Analysis). Prose phases and code phases are deliberately not mixed: a phase that
bundled `report-format.md`, which no test suite covers, with a script that several suites do
cover could not state an honest narrowed verification claim for its combined path set.

**The edit target is the source store** (`agent-system/extensions/core/**`), never a deployed
`.claude/**` path. The deployed tree is a gitignored, disposable artifact regenerated by the final
phase's redeploy.

### Research Integration

The research report settled where the check belongs (`validate-artifact.sh`, advisory-only,
gated to `report` and `plan` only — `summary-format.md` carries no carried-figure obligation),
established the flatten-before-matching mechanism on the evidence that real marks in the corpus
are line-wrapped, and ruled both "ALSO SETTLE" questions NO with grounds. Phase 3 records those
rulings; Phase 1 implements the mechanism.

One research finding did not survive plan-time re-derivation, and the correction is load-bearing
enough that Phase 1 is shaped around it. The report projected a flag count of zero against the
live corpus. Re-measured this authoring session over every file under `specs/` carrying the
literal token: the report's own file yields **13 opening-token occurrences against 8 complete
bracket matches**, a shortfall of five. Under the report's own condition 2 (flag a shortfall as an
unclosed mark) that is five spurious advisories on a single file, because nine of those thirteen
occurrences are *mentions* of the token — a backticked bare token, a `grep` command literal, a
regex literal — and not marks on a carried figure at all. Worse, flattening lets an unclosed
mention consume text up to the next closing bracket anywhere later in the file, which can absorb
and therefore hide a genuinely malformed mark that follows: a recall failure of exactly the class
that sank the rejected general detector.

A fix was measured this session and works: suppress an occurrence whose token is immediately
preceded by a backtick or a backslash, and bound the designator window. With that discriminator
every one of the seven corpus files carrying the token yields opens equal to complete matches and
zero empty designators, restoring a projected flag count of zero. Phase 1 therefore treats
mention-suppression as a required property of the check, not an optimization.

## Rollback/Contingency

Every phase is a source-store edit under `agent-system/extensions/core/**` and commits on its own,
so reverting is per-phase and ordinary: revert the phase's commit and redeploy. The deployed tree
holds no hand-authored state, so a redeploy from the reverted source store restores it exactly.

- **If Phase 1's corpus sweep shows the no-closing-bracket condition still fires on token
  mentions**: ship the empty-designator condition alone and carry the other forward to Phase 3 as
  a measured exclusion. Do not widen the match surface to compensate.
- **If Phase 2's corpus sweep reports more than a triageable handful of flags**: stop before
  Phase 3, report the count as a finding about the corpus, and do not ship an untriageable
  advisory. The boundedness criterion that sank the rejected general detector applies here too.
- **If Phase 7's composer change alters a dispatch file built with no prior artifact present**:
  revert that phase. Byte-identical-when-absent is a hard requirement, not a preference; every
  dispatch in the repository flows through that function.
- **If the final gate set goes red**: the failing gate identifies its phase, since each phase's
  own verification already ran green; revert that phase alone rather than the chain.
- **If an amended paragraph is found to contradict another sentence in the same file**: fix the
  contradiction in place within that phase. Do not defer it to a later phase — the consolidation
  of three records into one exists precisely so that one authoring pass owns the whole section.
