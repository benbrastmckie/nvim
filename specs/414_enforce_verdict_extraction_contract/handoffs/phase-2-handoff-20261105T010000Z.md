## Key Decisions Made

- The producer-side round-trip case (Case 9) compares the helper-selected line count against
  the lint's own `Total violations: N` summary line, not a raw `grep -c '\[VIOLATION\]'` over
  the whole captured output. A raw substring count over-counts: a flagged fixture line's own
  source text can legitimately re-quote the bracketed token (e.g. `grep -F '[VIOLATION]'`
  appearing inside the violation message's continuation after an embedded literal `\n` from the
  fixture's own `printf '%s\n'` is rendered as an actual newline by `echo -e`), producing a
  second physical display line that also contains the substring but is NOT itself a line-initial
  finding row. The summary line is the correct ground truth; this was discovered and fixed
  during Phase 2 itself (see `approaches_tried` in the progress file).
