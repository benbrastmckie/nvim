## Key Decisions Made

- `source_rel` (the source-store attribution prefix) is computed as `source_dir` resolved
  relative to ITS OWN git toplevel -- not relative to the consumer repository's root. This is
  what makes the universal `agent-system/extensions/<name>/...` spelling convention match
  correctly across repositories with unrelated directory layouts.
- The repository-containment parent-only resolution helper anchors a relative path's `dirname`
  at the passed `repo_root` explicitly (`_ssp_dirname_abs`), rather than relying on the caller's
  cwd equalling `repo_root` -- a library must not assume that.

## What NOT to Try

- Do not resolve a relative tested path's parent directory with a bare `realpath -m
  --relative-to=<repo_root_canon> -- "$(dirname -- "$path")"` without first anchoring the
  relative `dirname` output at `repo_root` -- `realpath` resolves a relative argument against
  the caller's cwd, not against an arbitrary `repo_root` argument, and this produced incorrect
  verdicts during initial manual testing.
