## Key Decisions Made (carry these into Phase 7, do not re-litigate)

- **D1/D2 resolutions**: implemented exactly as the plan specifies (see the plan's "Design
  Decisions" section) — nothing to revisit.
- **`--dispatch-seq`/`--dispatch-start-ts`/`--command-suffix` flags**: added beyond the plan's
  literal Phase 2 flag enumeration. Single-task mode has never persisted a per-cycle
  `dispatch_seq`/`dispatch_start_ts` anywhere (only the loop guard's cumulative
  `dispatch_seq_counter` survives across Bash invocations — the per-cycle value is an
  orchestrator-turn-local shell variable Claude already holds from Stage 4's `mint_dispatch_seq()`
  and `date -u +%s`). **Phase 7's single-task cutover MUST pass `--dispatch-seq "$dispatch_seq"
  --dispatch-start-ts "${dispatch_start_ts:-9999999999}"` explicitly** at its call site — these
  are NOT optional for single-task mode the way they are for multi-task (which can derive both
  from the multi-state file when omitted).
- **`is_live()` dry-run gating**: every mutating call in the script (defect recording, status
  transition, artifact link, round advance, commit, multi-state update, lock release) is gated.
  ONE deliberate, documented, non-gated exception: `skill_gate_completion_claim`'s own internal
  non-fatal `system-defect-record.sh` call in its Case 3/3 refuse branch — read `is_live()`'s own
  header comment in the script before "fixing" this.
- **stdout discipline (real bug found and fixed in Phase 6)**: `git-commit-scoped.sh`,
  `skill_postflight_update` (via `update-task-status.sh`), and `skill_link_artifacts` (via
  `generate-todo.sh`) all print their own diagnostic text to STDOUT with no redirect of their
  own. Every call site in `orchestrate-cycle-postflight.sh` now redirects these to `>&2` so the
  script's single-JSON-line stdout contract holds. **If Phase 7's cutover finds ANOTHER helper
  with this same leak, apply the identical fix (redirect the call site, not the shared
  function).**
- **Verdict mapping** (not fully specified by the plan; documented here since Phase 7's callers
  must interpret it): `ask_user` (user_decision present, highest precedence) > `failed`
  (off-schema, OR a genuinely unrecovered/non-infra-exempt missing outcome) > per-`dispatch_status`
  case (`researched`/`planned`→`ok`; `implemented`→`ok` if the completion-claim gate allowed, else
  `defer`; `partial`→`defer`; `failed`→`failed`; `blocked`→`blocked`) > `defer` (infra-exempt
  cycle, no outcome yet). Single-task callers should map this onto the existing `EXIT (partial)`/
  cycle-increment logic; multi-task callers already have an analogous case ladder to replace.
