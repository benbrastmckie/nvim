**Key Decisions Made** (see progress file `approaches_tried` for full detail):
1. The "degradation, override unwritable" case runs the fixture battery UNFILTERED rather than
   with `--only` -- a narrowed run skips the whole gate-lock acquire branch by design, so `--only`
   would never reach the code this case means to exercise.
2. The "degradation, every tier exhausted" case is tested as a direct CLI call
   (`gate-acquire-host`) against the fixture's deployed `task-lock.sh`, not through the full
   battery -- pointing the whole subprocess's `TMPDIR` at an unwritable path also breaks
   `run-all.sh`'s own internal `mktemp` usage (shared fixture build, `SUITE_OUT`, `OUT_DIR`),
   unrelated to the resolver. Tier 3 (`/run/user/$UID`) is defeated via a `UID=999999999`
   environment override for that one subprocess -- confirmed `UID` is not readonly in a
   non-interactive, non-login bash invocation, and this never touches the real `/run/user/$UID`
   or changes the process's real uid.

**Deviations from Plan**: The two degradation cases' exact invocation shape differs slightly from
the plan's literal phrasing (see the two inline annotations on Phase 4's checklist in the plan

`TMPDIR` for an entire `run-all.sh` battery subprocess -- it collides with that script's own
internal `mktemp` calls. Do not use `--only <suite>` to speed up a case that needs to observe the
gate-lock acquire branch -- narrowed runs skip it entirely.
