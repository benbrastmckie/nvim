## Implemented Design (what Phases 4-7 actually built; document THIS in Phase 8)

Renderer (`scripts/roadmap-integration.sh`, 542 lines):
- One render path for every store shape. Flags: `--print` (default), `--regenerate`, `--prune`
  (deprecated alias), `--roadmap`, `--state`, `--dry-run`, `--help`. `--max-tasks` is REMOVED;
  `context/patterns/roadmap-update.md` (two places) and `context/formats/roadmap-format.md` still
  mention it.
- Output order: line 1 the sentinel
  `<!-- generated by roadmap-integration.sh from specs/state.json; do not edit -->`; `# Roadmap`;
  one `- ` bullet per `primary_goals` entry (falling back to a single `active_goal` bullet); the
  table `| Milestone | Status | Tasks done | Review |` whose first column is
  `[{id}: {title}](#milestone-{id lowercased})` (or `_No milestones recorded._`);
  `See also: [Rules, conventions and repo context](#roadmap-context)`; one section per milestone
  in array order; `## Rules, conventions and repo context` last.
- Milestone section: `<a id="milestone-{id}"></a>`, `## {id}: {title}`, the `aim`,
  `- **Progress**: {status} -- {b_done}/{b} batches, {t_done}/{t} tasks done[ -- {note}]`
  (or `{status} -- no batches yet`), `- **Review**: {state}[ on `{ref}`][, {request}][ (updated {date})]`,
  `- **Gate**: {gate}` when present. Then per batch: `**Batch N** -- {description}[ (d/t done)]`,
  a fenced block holding `/orchestrate {open members}[ {flags}]` and one line per member
  (`{num} {token}` padded to 20 columns, title cut so the line is at most 100 characters,
  `   <- {roadmap_annotation}`), sorted by token rank then number. A batch with no open member
  is the single line `**Batch N** (done) -- {description}`. A closed milestone is its heading
  plus one line: `Closed {date}[ -- d/t tasks done] -- review: {...}[ -- {note}]`.
- Tokens: HOLD, IN FLIGHT, BLOCKED, PARTIAL, EXT-BLOCKED, `blocked:N[,M]`, `ready` (unchanged
  `status_token()`/`token_rank()`), plus `done` and `missing` for members that are not open.
  A member is done when terminal in `active_projects`, or absent from it and present in ANY
  archive list of the sibling `archive/state.json`.
- Last section: `<a id="roadmap-context"></a>`, then `### Repository` (`overview`), `### Rules`,
  `### Conventions`, `### Open tasks in no batch` (open tasks in no batch of a non-closed
  milestone); empty subsections are omitted.
- Not rendered: `rationale`, per-topic blocks, the coverage appendix, `## Next`, `## Open work`,
  `roadmap_notes`. `generate-task-order.sh` is not called.
- Output path: `roadmap_context.output_path` (repository-relative, `..` and absolute refused)
  unless `--roadmap` is given; default `specs/ROADMAP.md`.
- Write rule (the Destructive-Overwrite Refusal): `generated` -> write; `absent` -> write only
  when `roadmap_milestones` is non-empty, else a no-op NOTE; `classic`/`stage`/`unknown` ->
  refuse (exit 1, no write), message carries `(verdict: X)`, the sentinel, the file's headers and
  `migrate-roadmap-to-milestones.sh`.
- Stderr marker unchanged in shape: `runs=` = batches under non-closed milestones,
  `pruned=0`, `retained=0`. `OUTCOME:` lines unchanged in shape; the only layout value is
  `layout=generated`.

Preflight lib (`scripts/lib/roadmap-preflight-lib.sh`): `ROADMAP_GENERATED_SENTINEL`; verdicts
`absent | generated | classic | stage | unknown` (sentinel tested first); `scaffold` writes the
sentinel line alone onto an ABSENT path and refuses everything else (hand-authored files are
routed to the migration).

Migration (`scripts/migrate-roadmap-to-milestones.sh`): flags `--dry-run --force --roadmap
--state --retained PATH --session-id`; exit 0 ok, 1 usage or gate failure, 2 refused (already
migrated without `--force`, or the retained target exists; it is never overwritten), 3
prerequisite (`migrate-roadmap-next-to-state.sh`). One milestone `M1` "Current work" (active,
review none) wraps every flat batch unchanged; `## Goal` paragraphs -> `primary_goals` (bound
500); `## Standing rules` items -> `roadmap_context.rules`; `## Checks` and `## Settled decisions`
items -> `roadmap_context.conventions` (bound 300); over-bound items, non-item prose, the
preamble, `## Gate state`, `## Unfiled observations`, every other section and every
`roadmap_notes` string go verbatim to the retained-prose file (default
`archive/roadmap-retained-prose-YYYYMMDD.md` beside the state file). A classic file's `## Next`
and `## Open work` bodies are generated regions and are not accounted. Gate: multiset equality of
source lines against retained lines plus the recorded lines of state items; each state item
equals its lines joined; notes lines likewise; batches `jq -S` equal. Write order: retained
file, state (through `state-write.sh`, deleting the flat keys), generated file.

Conclusion script: `generated` -> regenerate and commit the accessor-resolved path;
`absent|classic|stage|unknown` -> the three-surface degrade, whose summary names the migration
for a hand-authored file. The advisory lint runs on every arm.

Callers (Phase 7): `skill-roadmap` Stage 1, `commands/todo.md` 6.6 and `commands/review.md` 6.8
proceed on `generated` and `absent`, and on `classic|stage|unknown` run the migration's dry run,
ask one `AskUserQuestion`, and run the migration with an explicit `--retained` path on approval.

## What NOT to Try

- Do not treat a green `verify-touched.sh` run as evidence for un-deployed source edits; with
  root `.` it executes the stale deployed suites. Use the resolver for selection and run the
  selection from the source store (see Critical Context 1-2).
- Do not run a long suite set as one foreground Bash call: the harness backgrounds a call at
  about 180 s, and `run-all.sh --jobs auto` buffers its result lines until the end.
- Do not expect `verify-deploy.sh --only-gate 3` to pass before the Phase 9 redeploy: it reports
  deployed-script drift and the `state-schema.json` `line_count` mismatch, both expected until
  then. Gate 4 passes now.
- Do not write a fixture named `state.json` containing `active_projects` from a Bash heredoc; a
  PreToolUse hook blocks the whole command. Write it with the Write tool, or under another
  filename.
- Do not run `roadmap-integration.sh` or the migration from the source store: the deploy-root
  guard refuses. Use a scratch `.claude/scripts/` tree (helper below) or the deployed copy after
  a redeploy.
