## Key Decisions Made

- `split_sections` locates sections by LINE-NUMBER POSITION from a single `grep -n '^## '` pass,
  not by re-matching header text the way `extract_section` does -- deliberately more robust
  against two stage sections sharing identical header text (not structurally impossible in a
  hand-authored stage layout, unlike the classic eight-literal-header vocabulary).
- Refactored `roadmap_has_orchestrate_fence` into a `body_has_orchestrate_fence` primitive
  (operates on an in-memory string) plus a thin file-reading wrapper, so `mode_regenerate_stage`
  can apply the same run-order predicate to an already-split section body.
- The classic path's pre-existing "no blank line before an appended coverage appendix following
  a fence" formatting quirk is intentionally also present in the stage path -- confirmed this is
  pre-existing behavior (reproduced it against the classic fixture via the SAME
  `"${authored}${new_coverage}"` concatenation pattern before touching anything), not a Phase 4
  regression, and out of this task's scope to fix.
