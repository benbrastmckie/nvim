## What NOT to Try

- Do not run the whole 22-case suite as the vehicle for every non-vacuity demonstration — it
  costs ~90-100s per run under current load. Guard G2's non-vacuity was demonstrated instead by
  extracting the comparison function and testing it standalone with simulated `run_vd` output
  (no suite invocation needed) — much cheaper and equally conclusive. Case (c)'s non-vacuity DID
  require a real suite run (the in-range-id-insertion demo), since it exercises the actual
  `verify-deploy.sh` arg-parse path.
- Do not mutate the suite's own `REGISTRY_IDS`/`REGISTRY_MAX` variables in-place to test G2 —
  doing so cascades into `ONE_PAST_MAX`, case32/33-equivalents, and every other case that reads
  those same variables, producing noisy unrelated failures. Test the comparison logic in
  isolation instead.
