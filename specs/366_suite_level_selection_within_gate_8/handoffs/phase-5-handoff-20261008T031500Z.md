## Key Decisions Made

- A concurrent sibling task had added 3 of its own entries to `manifest.json` at the same time
  this phase needed to add its own one entry. Since `git-commit-scoped.sh`'s `git add` always
  re-reads the full working-tree file (no partial-hunk staging), the sibling's 3 lines were
  temporarily removed from the working tree, this task's one-line fix was committed cleanly, and
  the sibling's 3 lines were restored into the (still-uncommitted) working tree immediately after
  -- verified via diff against a pre-edit snapshot that nothing was lost or altered.
- Full `verify-deploy.sh` (21 gates) was run once in this phase; of its 3 reported failures, only
  Gate 3 (doc-lint) had a component attributable to this task (now fixed). Gate 8 (run-all.sh,
  3 failures) matches Phase 1's load-flaky pattern. Gate 12 (state-writer boundary, 4 violations)
  is entirely in `test-session-registry.sh`/`test-task-lock-liveness.sh`, both declared in a
  concurrent sibling task's own file_scope -- confirmed via direct inspection, not assumed.

  the deterministic synthetic fixture for exact-match proofs.

  its own additive-only lines to the same array -- temporarily isolate your own hunk in the
  working tree first (see this phase's `approaches_tried` for the exact procedure).
