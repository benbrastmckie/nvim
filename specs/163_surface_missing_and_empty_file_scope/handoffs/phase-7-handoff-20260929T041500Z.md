## Deviations from Plan

- **MAJOR (Phase 7)**: writing the `--repair` D4 fixture revealed a genuine, pre-existing bug in
  `orchestrate-predispatch-review.sh --repair`'s write filter: plain `.field == null` (no
  `has()` guard) cannot distinguish an ABSENT key from a PRESENT literal null, so an absent-key
  candidate sharing a `--repair` invocation with a genuinely-null sibling had `file_scope: []`
  (or `dependencies: []`) silently manufactured onto it -- violating the script's own documented
  contract and this task's D4 guarantee. Confirmed pre-existing via `git show` against the
  pre-Task-163 commit and a manual reproduction. FIXED by gating both the preview `select()` and
  the write transform on `has(field) and .field == null`. This is a correctness fix to the
  EXISTING Class B repair machinery -- Classes F/G remain completely untouched by `--repair`, per
  D4/Non-Goals.
- **Phase 1 correction (load-bearing for Phase 5)**: `orchestrate-predispatch-review.sh` did NOT
  already splice `FILE_SCOPE_OVERLAP_JQ_DEFS` (contrary to the plan/research premise). Added new
  deploy-tree-only sourcing, matching `orchestrate-batch-admit.sh`'s `if ! . ...; then` idiom
  (required under `set -euo pipefail`, since the library's `read -r -d '' <<'JQDEFS'` heredoc
  idiom always returns non-zero at EOF).
- Fixed the pre-existing test harness (`test-orchestrate-predispatch-review.sh`) sandbox setup
  twice: once to add `lib/file-scope-overlap.sh` (Phase 5, required by the new sourcing), once to
  add `task-lock.sh` (Phase 7, required by the new `--repair` D4 fixture's `state-write.sh`
  mutex acquisition).
- Two literal apostrophes in an early draft of the Class F/G jq-block bash comments prematurely
  terminated the enclosing single-quoted jq program string, producing a bash syntax error --
  rewrote both comments apostrophe-free, matching the pre-existing convention already used
  elsewhere in this file's jq blocks.
- `${var:-{}}` as a jq-input bash default silently appends a stray trailing `}` when `var` is
  non-empty (bash parameter-expansion quirk, confirmed via isolated repro) -- fixed by using
  `${var:-null}` instead (Phase 2, `validate-state.sh`).
- Fixed a real `--help` regression in `validate-state.sh`: the hardcoded `sed -n '2,107p' "$0"`
  range silently truncated `--help` output once the header grew past line 107. Replaced with a
  dynamic `awk`-based range immune to further header growth.

## What NOT to Try

- Do not reintroduce a hardcoded `sed -n 'N,Mp'` range for `--help` in `validate-state.sh`.
- Do not use `${var:-{}}` as a jq-input bash default anywhere in this codebase's idiom -- use
  `${var:-null}`.
- Do not write an apostrophe inside a bash comment embedded in a single-quoted jq program string
  in either of the two edited scripts.
- Do not assume `--repair`'s write filter in `orchestrate-predispatch-review.sh` is scoped to
  only the specific field/candidate that has a defect -- it is scoped to the ENTIRE candidate
  set named on the invocation; the `has(field) and .field == null` gate (now present) is what
  keeps an absent key untouched, not the candidate-selection `select()`.
