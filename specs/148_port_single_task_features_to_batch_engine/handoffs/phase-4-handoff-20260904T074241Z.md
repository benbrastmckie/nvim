## What NOT to Try

- Do not re-derive any `PHASE_HEADING_ERE`/`PHASE_STATUS_OPEN_ERE`/`extract_phase_number` pattern
  inline anywhere — always `source`/`.` `scripts/lib/phase-heading-patterns.sh`.
- Watch for the `set -euo pipefail` hazard `orchestrate-cycle-plan.sh` already tripped once this
  task: any `grep`-based assignment that can legitimately find ZERO matches (e.g. "no OPEN heading
  left") MUST be guarded (`|| true`, `|| echo 0`, etc.) or the whole script aborts silently (no
  stdout, no stderr, exit 1) — this bit the Phase 4 Case D (no-open-heading fallthrough) test
  until `h1_next_heading=$(... ) || true` was added.
- `test-orchestrate-build-dispatch.sh` (and any suite using its `resolve_candidate` deployed-first
  pattern) tests the DEPLOYED `.claude/scripts/` copy, not the source store, unless
  `deploy-headless.sh` has been run since the last source-store edit — `test-orchestrate-cycle-plan.sh`
  and `test-orchestrate-churn.sh` are unaffected (they copy directly from `$CORE_DIR`, the source
  store). Redeploy before trusting a build-dispatch-suite result against a fresh edit.
- The plan-file trailer-append trap: this suite's (and `test-orchestrate-cycle-postflight.sh`'s)
  trailing `echo "Results..."` block has no `exit` statement in some files but DOES in others
  (`test-orchestrate-cycle-plan.sh`'s own trailer literally calls `exit 0`/`exit 1`) — appending
  new test groups via `cat >>` after that block makes them silently unreachable dead code. Always
  insert new groups with `Edit`, immediately BEFORE the trailer's `echo ""` line, never by blind
  append.
