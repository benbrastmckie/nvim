## Key Decisions Made
- Test suite drives the DEPLOYED `backfill-file-scope.sh` directly (no script-copying fixture):
  `backfill-file-scope.sh` itself has no `REPO_ROOT`/`deploy-root-guard.sh` dependency, but its
  sibling `state-write.sh` does, and `backfill-file-scope.sh` resolves that sibling via its OWN
  `SCRIPT_DIR` — so the whole chain only resolves correctly against a real deployed
  `.claude/scripts/` tree. Fixture isolation needs only a throwaway `specs/state.json` + plan
  dirs; nothing else needs copying.
- Found and fixed a real jq bug during test-writing: `map(if ($updates | has(.project_number|tostring)) ...)`
  silently no-ops, because a jq function argument is evaluated against the SAME input as the
  function call ($updates), not the outer `map(.)` item — so `.project_number` probed
  `$updates.project_number` (always null), never the task's own field. Fixed by binding
  `. as $item |` first and referencing `$item.project_number` explicitly. Caught by Case 2's
  positive assertion, not by code review alone — a reminder that a batched multi-entry jq filter
  needs an actual populated-array assertion, not just an exit-code check.
- Did NOT run the real cross-repo backfill in this phase — Phase 6 owns "run the real backfill...
  after dry-run inspection" and the uncommitted-in-BimodalLogic reporting (Decision 8).
