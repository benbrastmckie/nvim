## What NOT to Try

- Do not build a `specs_tree_is_gitignored()` test fixture with only a `.gitignore` file and no
  `specs/` directory on disk: `git check-ignore -q -- specs` answers "not ignored" for a
  nonexistent path regardless of a matching pattern. Always `mkdir -p specs/` in the fixture
  first. Logged via `issue-record.sh` (class "test-fixture-collision", severity minor). Not a
  production defect -- `init-specs.sh` always creates `specs/` in its own Step 1 before anything
  else runs.
- Same `verify-touched.sh` deployed-tree caveat as Phases 1-3 (already logged in Phase 2's
  handoff): a green `verify-touched.sh` result on the two test files here is a non-regression
  smoke check on the stale deployed copies, not a validation of this phase's new cases. The
  sourcestore-forced re-run above is the authoritative evidence for this phase.
